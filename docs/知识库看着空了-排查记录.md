# 知识库「看着空了」的排查（2026-09-23 实录）

## 现象

- 本地跑的时候知识库有文档；合并 4.5 上线后，列文档接口返回 **0 篇**，看着像知识库被删了。
- 实际：**百炼里 16 篇一篇没少**，问答检索也完全正常。

## 根因

4.5 引入**单库模式**（`SECRETARY_KB_SINGLE=1`，默认开）：管理面（`/kb` 页、`/api/kb/**`）只暴露 `.env` 的 `DEFAULT_INDEX_ID`。

| 面 | 用哪个索引 | 当时的实际值 |
|---|---|---|
| **检索面**（问答用 `kb_search`） | `config.KB_IDS` | `r57xtq9ypm`（16 篇，正常） |
| **管理面**（`/kb`、`/api/kb/**`） | `.env` 的 `DEFAULT_INDEX_ID` | **`igjhr8giyb`（另一个库，空）** |

两边不是同一个库 → 列文档接口返回 0 篇，还带 `"index_id":"igjhr8giyb"`、`"locked":true`。

## 判据（一眼分辨）

`GET /api/kb/indices/{你要的库}/documents` 的响应里，`index_id` 字段**不是**你请求的那个库 → 就是 `DEFAULT_INDEX_ID` 没对齐。

## 修法

把 `.env` 的 `DEFAULT_INDEX_ID` 改成**检索索引**（`r57xtq9ypm`），重启服务。本地与线上都要改。

修完实测：`/api/kb/indices` → 1 个库；`.../documents` → **16 篇**；`/kb` 页 200。

## 注意

- 上传规则文档用 `tools/kb_sync.py`（直连百炼 SDK），**不受单库模式限制**。
- `tools/deploy_update.py` 会**保留服务器 .env**，所以改一次会一直在；但换服务器/重建 `.env` 时要用 `.env.example` 对齐一次。
