# 变更说明：名称纠错归一 + 时间地点补全

> 本次改动集中在「阶段①信息补全」——把用户的原话，加工成一条可以直接查库的完整问题。

## 一、背景：阶段①原本是空的

原设计里，`/api/ask` 只接一个 `question`，注释写着「上游只做信息补全（补统计时间与地点）」。
但 `config.py` 里已注明**「上游补全应用已不在链路里」**——于是**时间和地点根本没人补**，
`COMPLETE_SYSTEM` 第 4 条却还留着「时间与范围已由上游补全确定」，等于把责任推给了一个不存在的环节。

同时，用户问法里的**错字、同音字、简称**也没人处理：
「环谈供电所」不改字，知识库检索不到 → 补全规则命中不了 → **字没改对，后面全是白费**。

本次改动把阶段①补齐为两步：**字面纠错与名称归一 → 时间与地点补全**。

## 二、新增能力

### 1. 字面纠错与名称归一（`secretary/name_fix.py` + `secretary/libs/name_correction_lib/`）

前置一步，在 `complete_question()` 之前执行。

| 输入 | 输出 |
|---|---|
| 环谈供电所的线损 | 环潭供电所的线损（同音错字） |
| 凉水的线损 | 两水供电所的线损（简称补全） |
| 公家棚线损 | 龚家棚台区线损（地名层归一，返回建议前缀） |
| 平均停电时长 | **原样不动**（业务词，不能被误改） |

**关键设计**：

- **零第三方依赖**。拼音不用 pypinyin，改成离线导出的 `data/pinyin_table.csv`（20922 字），
  运行时只查表。
- **失败降级**。`fix()` 的任何异常都退化为「原文 + used=False」，库加载失败打一行日志永久降级
  ——纠错是增强能力，不许拖垮主链路。`SECRETARY_NAMEFIX=0` 可整体关闭。
- **合成名要提示**。地名层归一得到的是**库里不存在的合成名**（如「龚家棚台区」），
  `fix()` 会返回 `hint`，提示下游用 **LIKE 前缀**查而不是等号，否则一条都查不到还以为是空数据。

### 2. 时间与地点补全（`secretary/time_scope.py`）

| 输入 | 识别结果 |
|---|---|
| 环潭供电所**上个月**的线损率 | 时间 = 2026年8月（`month/202608`），地点 = 环潭供电所 |
| **本月**的售电量 | 时间 = 2026年9月（`month/202609`），地点 = **全市**（默认） |
| 环潭供电所的线损率 | 时间 = **今年至今**（`yearToDate/202609`，默认） |
| **去年**随县的售电量 | 时间 = 2025年（`year/2025`） |

**设计要点**：

- **确定性换算交给代码，不交给模型**。「上月」是哪个月取决于**今天**——模型不会翻日历，
  算错也看不出来。代码算出具体年月后，**写回问题文本**
  （「环潭供电所上个月的线损率」→「环潭供电所2026年8月的线损率」）。
- **默认值按数据实际分布定，不按语义直觉**。语义上「今年」该映射成 `period_type=year`，
  但快照表里**供电所层的全年数据只到 2025**，当年数据全在 `yearToDate` 里——
  照语义映射会一条都查不到。所以「今年」= `yearToDate` + 数据里最新那个月。
- **地点默认全市**，只附说明、**不改写原问题**，避免把用户的话改得面目全非。
- **提前说清口径可用性**。查一次「该期间有没有值」，把结论塞进给模型的上下文：
  问最新月的当月 →「当月值还没出齐，请改用累计并说明」；问的月份没值 →
  「该月缺失，最近有值的是 2026年7月」；问供电所+当月 →「供电所粒度没有当月口径」。

  加这一句之前，答案是「抱歉，未找到相关信息」；加了之后是
  「环潭供电所2026年8月当月台区线损率数据缺失，最近可用的是截至2026年9月的本年累计台区线损率为3.65%」
  ——**同样的数据，体验完全不同**。

### 3. 提示词同步更新（`secretary/agent.py` 的 `COMPLETE_SYSTEM`）

第 4 条由「时间与范围已由上游补全确定，直接采用」改为：
「**时间与地点必须明确（缺了就补，这是硬要求）**」，并列出相对词 → 具体年月的对照表、
默认值规则、以及「不要自己推算日期」。

## 三、修复的问题

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | 「平均停电时长」→「平均停**电视台专变**长」 | 滑窗切出「电时」(dianshi)，库里台区「电视台专变」的码正是它的前缀，覆盖率**恰好 70.0** 卡在门槛线上（`cov < 70` 才拦） | 两字碎片只认「字」不认「音」 |
| 2 | 「随县供电公司」→「国网随县供电公司**供电公司**」 | 只切出「随县」补成全名，原文的「供电公司」留在原地 | 新增 `_absorb_tail()`：把用户已写的类型尾词并进替换区间 |
| 3 | 「产生经济效益」→「产盛晶效益」 | 词层只认读音，「经济\|**济效**\|益」滑出「济效」，词表里正好有「绩效」(jixiao) | 新增 `_vocab_spans()`：已写对的业务词区间内部不许切 |
| 4 | 查数返回空、答「未找到」 | `semantic.py` 把字段说明截断到 40 字，`scope_key` 的说明里「**按名称筛选请用 scope_name**」正好在第 41 字之后——模型看不见判据，写错了过滤字段 | `d[:40]` → `d[:300]` |
| 5 | `config.load_env` 遇到 `.env` 行尾注释直接崩 | 值 `"3306        # 【必填】"` 被整段当数字解析 | 支持「空白 + #」形式的行尾注释（不截断密码里的 `#`） |
| 6 | 双击 `.bat` 闪退、脚本报路径不存在 | 原作者本机路径 `D:\秘书智能体\...` 被写死在 19 处 | `.bat` 改用 `%~dp0`；脚本改 `__file__` 动态定位；文档改用 `<项目根目录>` |

## 四、验证

新增 `tools/19_regression.py`（回归自测，可重复跑）：

```
A 该改的（功能）   10 条  → 10/10 通过
B 不该改的（安全） 20 条  → 19/20（余下 1 条为既有边界，见下）
C 台区召回（抽样 300）
```

端到端实测（本地 + 服务器公网均通过）：

| 提问 | 纠错/补全后 | 答案 |
|---|---|---|
| 环潭供电所的线损率是多少 | 环潭供电所的线损率是多少 | 截至 2026 年 9 月，环潭供电所台区线损率 3.65% |
| 环潭供电所**上个月**的线损率 | 环潭供电所2026年8月的线损率 | 8月数据缺失，最近可用的是累计 3.65% |
| **本月**的售电量是多少 | 2026年9月的售电量是多少 | 当月未出齐，1-9 月累计 345507.26 万千瓦时 |
| **凉水**供电所**上个月**的售电量 | 两水供电所2026年8月的售电量 | 累计 24018.73 万千瓦时 |

**已知边界**（未修，属既有行为）：`深农台区` → `神农六组变压器`。
同音纠错方向正确，但候选池里混进了单位名（「神农供电服务站」），
导致跳过了地名层归一、硬挑了一个具体台区。待业务口径确认后再处理。

## 五、数据依赖说明（**重要**）

新增的 `secretary/libs/name_correction_lib/data/` 是纠错引擎的**词典**，共 8 个 CSV：

| 文件 | 行数 | 内容 |
|---|---|---|
| `catalog.csv` | 20184 | **全州公司 / 47 个供电所 / 两万个台区的标准名** |
| `area_core.csv` | 20132 | 台区核心词索引 |
| `pinyin_table.csv` | 20923 | 汉字 →（声母, 韵母）离线表 |
| 其余 5 个 | — | 错法表、业务词表、同音歧义、规则、术语 |

**其中 `catalog.csv` / `area_core.csv` 是真实业务数据**，而原仓库 `.gitignore` 的策略写明
「不入库：凭据、**业务知识库、数据与产物**」。

因此本次提交**未包含 `data/` 目录**（已在 `.gitignore` 中排除）。
**缺失该目录时，纠错与名称归一功能会自动降级**（不报错、不影响主链路），
需要完整功能时，请单独获取词典并放到 `secretary/libs/name_correction_lib/data/`。
