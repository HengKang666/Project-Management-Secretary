# 技能规划与问题清单

> **先有问题，再有技能。** 每个技能都从「一组可以直接照着问的问题」开始 —— 问得出、答得对，才值得固化成技能。
> 每条问题后面标了**依据什么数据**和**怎么触发**。触发方式三类：**手动词**（人主动问）、**定时**（每天/每周跑）、**状态变更**（数据变了就触发）。
> ☑ 已做 ｜ ○ 待做

# 一、预算侧

## 1. 预算分配 ○（手动词）

**视角**：市公司 / 县公司（分配方）　**触发**：手动词；每年一次，也可随时复盘

| # | 可以直接问的问题 |
|---|---|
| 1 | 今年预算怎么分的？各二级公司、各供电所分别分到多少、占比多少？ |
| 2 | 为什么某某供电所分这么多？它的得分是怎么构成的？哪几项分高、权重多大？ |
| 3 | 跟去年比，谁多了谁少了？差额主要出在哪几项上？ |
| 4 | 这次分配有没有明显偏高的？按规则它应该拿多少？ |

**依据**：分配金额、16 项得分（原始值/标准分/加权分/名次）、权重、评分规则原文
**注意**：得分高 = 越该投入，不是表现好；有「原始值为 0」的项要标数据缺失

## 2. 项目申报自审 ○（手动词）

**视角**：供电所 / 项目申报人（报之前自己先过一遍）　**触发**：手动词；申报前自查

| # | 可以直接问的问题 |
|---|---|
| 1 | 我这个项目能不能报？还差哪些条件或材料？ |
| 2 | 我这个项目报多少预算合适？依据是什么？ |
| 3 | 我这个项目该归到哪个缺陷类型？ |
| 4 | 我这个所的预算还剩多少？再报几个会不会超？ |

**依据**：申报条件规则、同类项目的历史金额、缺陷类型字典、本单位预算余额
**注意**：同类项目金额要给分布（最低/中位/最高），不能只给平均数

## 3. 各层级审批（不同角色） ○（状态变更 + 手动词）

**视角**：**按角色分** —— 供电所内部审核 / 县公司运检部 / 营销部 / 县公司财务部
**触发**：状态变更（有单子进到我的节点）；也可手动词

| # | 可以直接问的问题 |
|---|---|
| 1 | 我这个角色现在有多少待审批的？分别是哪些项目？ |
| 2 | 我这个节点上，卡得最久的是哪几个？卡了多少天？ |
| 3 | 这个项目我该不该批？依据是什么？ |
| 4 | 我批过的项目后来进度怎么样？ |

**依据**：当前节点、审批任务、工单状态、计划时间、项目详情
**注意**：**同一个问题问不同角色，答案应该不一样** —— 必须先确认提问人角色，再决定给哪些项目

## 4. 预算执行 ☑（手动词）

**视角**：全市 / 二级公司 / 供电所　**触发**：手动词；也可定时
**已做成**：skills/预算执行情况分析.md（四问）

| # | 可以直接问的问题 |
|---|---|
| 1 | 预算执行情况？（分配多少、已审批多少、占比多少）|
| 2 | 是否达到任务标准？ |
| 3 | 什么原因？ |
| 4 | 下一步建议？ |

## 5. 实时监控（阈值 + 自回归提醒） ○（定时）

**视角**：各级管理者　**触发**：**定时**（每天 8:30）；越阈即推，不静默

| # | 可以直接问的问题 |
|---|---|
| 1 | 现在有哪些指标越过阈值了？ |
| 2 | 我这个层级今天最该关注的三件事是什么？ |
| 3 | 有哪些单位或项目连续两期在恶化？ |
| 4 | 阈值是多少、谁定的、越了该提醒谁？ |

**依据**：**阈值配置（要先建：指标 / 阈值 / 生效层级 / 提醒对象 / 提醒频次）**、六项指标快照、工单状态
**注意**：阈值必须是**配置**，不写在代码或提示词里；提醒要说清「越了多少、超了多久、该谁管」

# 二、项目侧

## 1. 审批（规则判定） ○（状态变更 + 手动词）

**视角**：审批人　**触发**：状态变更；也可手动词

| # | 可以直接问的问题 |
|---|---|
| 1 | 这个项目符合审批条件吗？逐条过一遍给我看 |
| 2 | 不符合的是哪几条？怎么改才能通过？ |
| 3 | 这类项目以前批过多少、平均多少钱？ |
| 4 | 有没有材料不齐 / 类型填错 / 金额超限的？ |

**依据**：**审批规则（要先成文：什么类型的项目、满足什么条件、能不能通过）**、同类历史项目
**注意**：规则要**逐条给结论**（符合/不符合），不要给笼统的「基本符合」

## 2. 风险预控（资金合理性） ○（状态变更 + 手动词）

**视角**：审批人 / 财务　**触发**：状态变更（新单进来）

| # | 可以直接问的问题 |
|---|---|
| 1 | 这个项目申请 X 万，合理吗？同类的都花多少？ |
| 2 | 有没有虚高的迹象？单位造价、工程量、物资占比跟同类比怎么样？ |
| 3 | 这个所今年还剩多少预算？批了会不会超？ |
| 4 | 这个项目里工程费和物资费的比例正常吗？ |

**依据**：同类项目金额分布、工程/物资明细、单位造价、本单位预算余额
**注意**：结论要给**可比对象**（拿哪几个项目比的），不能只说「偏高」

## 3. 项目流程实时监控（按角色预警） ○（状态变更 + 定时）

**视角**：项目各角色（申报人 / 审批人 / 施工方 / 验收人）
**触发**：状态变更 + 定时；**对不同角色推不同预警**

| # | 可以直接问的问题 |
|---|---|
| 1 | 现在有哪些项目卡在我这个环节？ |
| 2 | 哪个项目该往下一环节推了？ |
| 3 | 有哪些项目已经超期了？超了多久？ |
| 4 | 今天 / 本周需要我处理的清单是什么？ |

**依据**：工单状态流转、当前节点、计划与实际时间、责任人
**注意**：**先定角色，再给清单**；预警要带「卡了几天」和「下一步该谁动」

## 4. 项目执行进度异常提醒 ○（定时）

**视角**：项目负责人 / 管理层　**触发**：定时（每周）+ 越阈即推

| # | 可以直接问的问题 |
|---|---|
| 1 | 哪些项目进度异常？（计划 vs 实际）|
| 2 | 哪些项目该完工还没完工？拖了多久？ |
| 3 | 哪些项目钱花了但进度没动？ |
| 4 | 按当前进度，哪些项目年内完不成？ |

**依据**：计划/实际时间、工单状态、金额、剩余时间
**注意**：异常要有**判据**（超期多少天、落后多少算异常），判据要能配置

# 三、报告类

## 1. 决算书 / 验收报告（项目完工后生成） ○（状态变更）

**视角**：项目负责人　**触发**：状态变更（项目完工 / 验收完成）→ 自动生成

| # | 可以直接问的问题 |
|---|---|
| 1 | 这个项目的验收报告怎么写？按模板给我一版 |
| 2 | 决算书要包含哪些内容？ |
| 3 | 这个项目最终成效是多少？跟申报时预计的比怎么样？ |
| 4 | 这个项目还有哪些资料没归档？ |

**依据**：项目实际数据、实际金额、六项成效、**报告模板（要先有模板）**
**注意**：模板是**数据**（可换），文档是**规范**；最终成效要跟**申报时的预计值**对照，说清达成与未达成

# 四、构建顺序建议

| 顺序 | 技能 | 为什么先做 |
|---|---|---|
| 1 | 各层级审批（按角色）| 数据全在（工单 + 节点 + 审批任务），一问就见效 |
| 2 | 项目执行进度异常 | 数据全在（计划/实际时间 + 状态），判据好定 |
| 3 | 项目申报自审 | 数据全在，能前移拦截问题 |
| 4 | 预算分配 | 数据全在（得分 + 权重 + 规则）|
| 5 | 风险预控 | 需要先定「同类可比」口径 |
| 6 | 审批（规则判定）| **需要先把审批规则成文**（现在规则可能只在人脑里）|
| 7 | 实时监控 / 流程监控 | **需要先建阈值配置和角色清单** |
| 8 | 决算书 / 验收报告 | **需要先有模板** |

**三个前置依赖（不解决就做不了）**：
1. **审批规则**要成文（否则「该不该批」只能靠人）
2. **阈值配置**要建（否则「监控」没有判据）
3. **报告模板**要定（否则生成的报告不可用）

# 五、每个技能文档的固定骨架（照抄）

1. **你是谁、在答什么** —— 角色 + 一组固定问句（几个问句就是几段）
2. **先定层级 / 角色** —— 视角错了后面全错
3. **逐段怎么写** —— 每段：要拿到哪些数、怎么对比着写、判断口径是什么、有哪些坑
4. **最容易犯的错** —— 自查清单
5. **回答里不许出现的东西** —— 表名字段名、技术声明、过程叙述
6. **全篇硬规则** —— 数字有出处、查不到写未查得、先结论后依据

> **表名与字段名一律不写进技能文档** —— 靠业务字典定位，换一套库不用改文档。
