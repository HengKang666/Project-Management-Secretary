# 微调数据方案（针对"把口径与方法训进去"）

> 承接《微调方案讨论.md》。上一条我把口径、公式和数值一起归到"事实"里劝退了 —— 这不准确。
> 口径/公式/维度规则是**稳定、有限、高频**的知识，属于**可以训、而且值得训**的那一类。本文件专门讲怎么造这类数据。

## 一、先修正分类：口径与方法 ≠ 数值

| 类别 | 例子 | 变化频率 | 能不能训 |
|---|---|---|---|
| **口径 / 公式 / 维度规则** | "线损率怎么算"、"报告要关注哪些维度"、"执行率=执行金额÷预算金额" | 一年改不了几次 | ✅ **可以训，收益明确** |
| **数值** | "2026年9月线损率 2.61%" | 每月变 | ❌ 绝对不能 |
| **结构与关系** | "哪个指标在哪张表" | 跟着表结构变 | ⚠️ 可训，但要留检索兜底 |

判断标准就一条：**这条知识是"怎么做事"，还是"现在是多少"？** 前者可以训，后者必须查。

## 二、他举的两个例子，分别是什么、怎么造

### 例 1：「线损率怎么计算」

这是**口径知识**，答案里有三样东西：① 定义（输入电量与售电量之比）② 数据源（分三级：全市/区县看月度汇总表、所级看成效表、台区看台区表）③ 陷阱（当月值字段与累计值字段不同、不能简单平均）。

**造数据的方式**（不是写成一段话让它背，而是拆成三种样本）：

| 样本形态 | 例子 | 训练的作用 |
|---|---|---|
| **定义型** | 问：线损率怎么算？→ 答：输入电量减售电量再除以输入电量；全市/区县在 X 表 loss_rate，所级在 Y 表 line_loss_current；比率类不能简单平均。 | 注入口径 |
| **决策型** | 问：今年随县线损率多少？→ 完整轨迹：run_sql 选对表+选对 summary_type → 答 2.96%（累计口径） | **真正治"选错表/选错字段"** |
| **防守型** | 问：全市线损率是所有台区线损率的平均吗？→ 答：不是，比率不能简单平均，且各层级口径不同，不能互相推导。 | 治理解偏差 |

**只训定义型是不够的**：模型能背出"分三级"，但一到实际提问仍然会选错表 —— 这是我们在实测里看到的（它就是挑了 currentMonth 那行空的，然后说"查不到"）。**决策型样本才是重点。**

### 例 2：「报告关注哪些维度」

这是**方法/模板知识**，属于微调最擅长的"模式学习"。

来源现成：你的《电力业务口径文档》里已经有 —— 供电所成效 6 项指标、台区成效 2 项指标、大屏展示口径、业务查询回答模板（统计范围/统计时间/数据来源/指标范围/工单条件/结果说明）。

**造法**：把"要一份 X 报告"变成固定输出模式：

    问：给我一份各供电所的成效报告
    → 答：按 6 项指标组织：售电量 / 线损率 / 意见工单 / 故障报修工单 / 用户平均停电时长 / 故障跳闸次数，
       每项注明统计时间（本月 or 当年累计）、统计范围、数据来源；
       排名时标明截止月份；缺失值写"暂无数据"，不按 0 处理。

这类样本 50–100 条就能训出稳定的输出模式（因为它学的是结构，不是内容）。

## 三、数据生成流水线（从文档到训练集）

    口径文档 / 数据地图（唯一事实源）
        │  ① 切条目：一条知识 = 一个条目（公式 / 数据源 / 陷阱 / 维度清单）
        ▼
    知识条目表（人工过一遍，确保准确）
        │  ② 问法扩增：每条知识造 3–5 种问法
        │     口语版（"线损咋算"）/ 正式版（"线损率的计算口径"）/ 反例版（"是不是取平均"）
        ▼
    候选样本（每条 = 问题 + 期望答案 + 期望工具轨迹）
        │  ③ 人工判定：对 / 错 / 未查库 三类打标（沿用现在报告里的判定标准）
        ▼
    训练集 JSONL  +  独立评测集（留没见过的问法）

**第 ② 步的扩增可以自动做**（让大模型基于文档改写问法），但**第 ③ 步必须人工**——混进去一条错答案就是教坏一条。

## 四、数量预算（经验值）

| 知识类型 | 来源 | 造法 | 目标条数 |
|---|---|---|---|
| 口径 / 公式（15 组） | 口径库 + 电力业务口径文档 | 每条形 3–5 问法 × 3 形态（定义/决策/防守） | 150–300 |
| 报告维度 / 模板 | 口径文档第 5、19、21 节 | "给我一份 X 报告" → 固定维度清单 | 50–100 |
| 表用途（133 张） | 数据地图 | "X 的数据在哪张表" → 表名 + 字段 | 200–400 |
| 拒答（负样本） | 现在就能造 | 超范围 / 库里没有 / 粒度不支持 | 150–300 |
| **真实轨迹** | 线上/页面日志 | trace 落盘，人工判定 | 持续累积 |

合计 **约 600–1200 条**可以支撑第一轮 LoRA；1200+ 条更稳。

## 五、训练配置（常规做法，非本机实测）

| 项 | 建议 |
|---|---|
| 基座 | qwen3.6 系列（27B / 35B-A3B 这类可自部署的）；也可先用 3.8-27B 对照 |
| 方法 | **LoRA**（rank 8–32，只训注意力与 MLP 投影层），比全参省显存、遗忘更轻 |
| 框架 | 开源路线：ms-swift（Qwen 官方生态）或 LLaMA-Factory；云端路线：百炼自带的模型调优 |
| 数据格式 | Qwen 的 chat 格式（messages 数组）；工具调用样本直接用 OpenAI tools 字段 |
| 轮次 | 1–3 epoch，宁少勿多（知识型任务容易过拟合） |
| 学习率 | 1e-4 ~ 2e-4（LoRA 常用档），配 5–10% warmup |

## 六、怎么验收"训进去了"（三个测试，缺一不可）

1. **闭卷口径测试**：**关掉知识库**，问 50 条口径题（含"线损率怎么算"这类），看答对率 —— 基线 vs 训后。
2. **下游任务测试（最关键）**：同样 15 道数据题，**关掉 kb_search**，只看它能不能选对表、选对字段、选对口径、算对数字。**这才是"不依赖知识库也能判断"的真正判据。**
3. **幻觉测试**：问 20 条库里根本没有的指标（比如"台区低电压治理率""客户满意度指数"），看它是不是也开始编口径。
   → 这一条必须做：Gekhman 那篇的结论就是"新事实训多了，幻觉倾向上升"，知识注入型微调尤其要盯着这个数。

## 七、最大的风险：知识变成两份

训完之后，**权重里一份、文档里一份**。口径一改，两边就会不一致，而且**冲突时没人察觉** —— 这和上一版"两套路由并行"是同一种病。

三条对策（选一条，必须选）：
1. **文档是唯一事实源，模型版本绑定文档版本**：文档改版 → 标记模型需重训；页面上显示"模型口径版本"。
2. **保留检索兜底**：回答时若检索到与模型口径冲突的内容，以文档为准并告警。
3. **口径变更走回归**：每次口径改动，跑一遍闭卷测试，看模型是不是还答旧口径。

## 八、一句话

**训口径和方法是划算的**（稳定、有限、高频，正是权重擅长的事）；**训数值是自杀**。
但训完之后，"文档是唯一事实源"这条必须守住，否则你会得到两个互相矛盾的大脑。
