# 工具说明（模型可以调用的 5 个工具）

> 这 5 个工具是模型与外部世界之间**唯一**的通道。工具的定义（名称、参数、说明）写在代码里；
> **"什么时候调哪个、调几次、够不够"全部由模型自己决定**，代码不做任何业务判断。

## 总览

| # | 工具 | 一句话 | 数据来自 | 是否算"查过库" |
|---|---|---|---|---|
| 1 | kb_search | 查口径与业务背景 | 百炼知识检索服务 | 否（只算查过知识库） |
| 2 | find_column | 按字段名/中文注释全局搜字段 | information_schema | 是 |
| 3 | list_tables | 列出表（名称/注释/行数/用途标记） | information_schema | 是 |
| 4 | describe_table | 看某张表的完整字段 + 2 行样本 | information_schema + 该表 | 是 |
| 5 | run_sql | 只读执行 SELECT 取数 | 业务库 dlj_data | 是（唯一的数据来源） |

---

## 1. kb_search —— 查口径与业务背景

**作用**：把"业务黑话、指标口径、统计范围、数据来源"弄清。它**只返回文档切片**，不返回模型生成的答案（一份答案只有一个出口）。

**调用**：kb_search(query, top_k=5)

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| query | string | 是 | 检索意图，可以是"线损率 口径"这样的短语 |
| top_k | int | 否 | 返回几条，默认 5 |

**返回**：
    {
      "total": 5,            // 命中切片总数
      "cost_time": 287,      // 检索耗时（毫秒）
      "nodes": [
        {"score": 0.9302, "doc_name": "口径库", "title": "2.2 预算执行金额与执行率",
         "content": "表：t_power_company_assessment 字段：year、budget_amount、budget_execution_amount 公式：..."}
      ]
    }

**底层**：POST 百炼知识检索接口（agent_id 为专用检索服务），请求体只要 query 与 images，检索策略全部锁在服务端；返回按相关度排序的切片。

**什么时候用**：① 问题里有业务术语、缩写、口径不明的词；② 要先知道"这个指标该查哪张表/哪个字段"；③ 要判断某问题是否超出业务范围。

**不要用它取数**：知识库里的数字是历史文档值（如 2025 年数据），**不能当答案**，只能当背景。

**失败**：返回 {"error": "...", "nodes": [], "total": 0}。实测过的错误：agent 未发布、query 缺失、kb 未绑定。

## 2. find_column —— 按字段名或中文注释全局搜字段

**作用**：回答"这个数据在哪张表"。133 张表 1956 个字段，靠表名猜常常猜不到，但字段的中文注释往往写着业务含义。

**调用**：find_column(keyword)

**返回**：表名 + 字段名 + 类型 + 中文注释，最多 80 行。

    例：find_column("线损") →
      t_power_company_assessment.line_loss_current       decimal  当前线损率
      t_power_company_assessment.station_line_loss      decimal  所级线损
      t_power_push_city_month_summary.loss_rate         decimal  累计线损率
      t_power_push_city_month_summary.month_loss_rate   decimal  当月线损率
      t_power_area.loss_rate                            decimal  台区线损率
      t_power_station_monthly_core_stat.line_loss_rate  decimal  供电所月度线损率

**什么时候用**：不确定字段名；或者知道业务名但不知道库里怎么命名（"执行金额"可能是 budget_execution_amount，也可能是 reality_total）。

**限制**：只搜字段名与字段注释，不搜表注释（搜表用 list_tables）；最多 80 条，关键词太泛会淹。

## 3. list_tables —— 列出表

**调用**：list_tables(keyword) —— keyword 可选，按表名或表注释模糊筛。

**返回**：表名、中文注释、估算行数、更新时间，以及代码附加的**用途标记 note**：

| note | 触发条件 | 含义 |
|---|---|---|
| 备份/暂存，勿当数据源 | 表名含 _bak_ / _copy / _old / _ago_img_ / stg_ | 历史副本或暂存表，**不要用** |
| 中台推送结果 | 表名以 t_power_push_ 开头 | 中台同步下来的结果数据，最常用 |
| 定额/价格 | 表名以 t_cost_ 开头 | 施工定额与物料价，不是实际支出 |
| AI 辅助表，非业务事实源 | 表名以 ai_ 开头 | 不参与业务指标 |

**重要**：估算行数是 InnoDB 的统计值，**可能严重偏离**（曾出现估算 25 万、实际 0 行）。要判断有没有数据，必须用 run_sql 先 COUNT 一次。

---

## 4. describe_table —— 看一张表的结构

**调用**：describe_table(table)

**返回**：全部字段（字段名、类型、是否可空、中文注释）+ **前 2 行真实样本**。

**为什么要带样本**：状态码这类字段，注释常常是空的，但样本行能看出取值长什么样（配合口径库里的状态码表就能读懂）。

**安全**：表名必须匹配字母数字下划线，防注入。

**限制**：最多 300 列；样本查询失败会在返回里附带 sample_error，不影响字段列表。

---

## 5. run_sql —— 唯一的数据来源

**调用**：run_sql(sql)

**返回**：
    {"columns": ["stat_month","loss_rate"], "rows": [{"stat_month":"202609","loss_rate":"2.6100"}],
     "row_count": 1, "sql": "SELECT ... LIMIT 200"}
失败时返回 {"error": "ProgrammingError: (1054, \"Unknown column 'xxx' in 'field list'\")"} —— 错误同样会回灌给模型，让它自己改写 SQL。

**只读安全闸（纯保险，不含业务判断）**：

| 闸 | 规则 |
|---|---|
| 语句类型 | 必须以 SELECT 或 WITH 开头 |
| 危险字符 | 不允许 ; 、-- 、/* 、*/ |
| 行数 | 没有 LIMIT 时自动补 LIMIT 200；取回最多 200 行 |
| 超时 | SET SESSION MAX_EXECUTION_TIME = 25000（25 秒） |
| 连接 | 每线程一条连接；每次用前 ping 探活；断了自动重连；连接类错误原样重试一次 |
| 账号 | 只读账号只跑 SELECT，写不进去 |

**模型自己写 SQL，但不写库**：它只能 SELECT；表名、字段名都要真实存在（不存在就报 1054，它自己改）。

**性能提示（已写进系统提示）**：排名、极值、计数让数据库算（ORDER BY / LIMIT / COUNT / GROUP BY），不要把上万行取回来自己看。

## 为什么只有这 5 个工具

1. **取数只有一个出口**：数据必须经过 run_sql，回答里的每个数字才追得回来。知识库、互联网都只提供背景。
2. **找表拆成三级**：list_tables（有哪些表）→ find_column（字段在哪）→ describe_table（长什么样）。粒度小，模型可以按需逐级深入，不用一次吞下 133 张表的全部结构。
3. **不提供"一次问到底"的业务技能**：上一版把"域 × 加工方式"做成 16 个技能，结果新问法进不来，只能不停加关键词。现在把知识放到外部文档、把动作缩到 5 个通用工具，新问法不再需要改代码。
4. **工具不带业务规则**：工具只负责"取"，"该取什么、取几次、够不够"全在模型。

## 工具调用的失败与兜底

| 情况 | 现在的行为 |
|---|---|
| SQL 写错（列名不存在） | 错误原文回灌给模型，它自己改写重查（实测常见，能自愈） |
| 连接断了 | 自动重连 + 重试一次；仍失败则把错误回灌，模型如实说"数据库连接异常" |
| 知识库不可用 | 返回 error 字段，模型据此判断是否降低回答置信度 |
| 一个问题都没查就作答 | 提醒一次；仍不查 → 拦下，返回"未核实，不予作答" |
| 查太久不收手 | 剩 3 步开始，每步提醒"你还有 N 次机会，请尽快收手" |
