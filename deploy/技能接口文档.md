# 项目管理秘书 · 技能接口对接说明

> 给你们对接用。**线上地址：`http://47.121.183.81:8200`**（无需鉴权，内网/公网均可直连）。
> 自检：`curl -s http://47.121.183.81:8200/health` → 四个字段都要 `true`：
> `{"ok":true,"name_fix":true,"qa_log":true,"kb":true}`

---

## 一、接口总览

| 接口 | 方法 | 用途 |
|---|---|---|
| `/api/skill/title` | POST | **定时任务用这个**：只回一句话标题（无异常也回） |
| `/api/ask` | POST | 常规问答：查数直接答；分析题额外返回分析页面 HTML |
| `/api/skill/run` | POST | 手动/提交前/状态变更类技能，要一整段回答时用 |
| `/api/skills` | GET | 列技能清单（含定时技能列表） |
| `/health` | GET | 服务与附属能力自检 |

历史会话、知识库上传等接口见同目录《接口对接说明.md》《知识库接口文档.md》。

## 二、定时触发：POST /api/skill/title ★

**约定：这个接口永远有返回。** 没有异常时也回 `status:"ok"` 和一句话标题，
**不存在空返回**；**无异常展示什么由你们决定**，我们只负责给标题。

### 请求

```json
{ "skill_id": "flow-monitor", "account": "sz002", "when": "2026-09-22 08:30" }
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `skill_id` | ✅ | 定时技能 ID，见下表 |
| `account` | 建议 | 触发账号（决定数据范围），见下表 |
| `when` | 可选 | 触发时间，默认当前时间 |
| `scope` | 可选 | 覆盖数据范围，不传按技能默认 |
| `model` | 可选 | 指定模型，默认 `qwen3.8-max` |

### 响应

```json
{
  "skill_id": "approval-role",
  "name": "各层级审批（不同角色）",
  "status": "abnormal",
  "count": 13,
  "title": "今天有 13 个项目在县公司财务部审核节点积压超90天",
  "checked_at": "2026-09-22 11:32:10",
  "triggered_at": "2026-09-22 08:30",
  "account": "xgscwb001",
  "role": "县公司财务部审核",
  "scope": "国网随县供电公司",
  "tool_calls": 2,
  "elapsed_ms": 10324
}
```

| 字段 | 说明 |
|---|---|
| `status` | `abnormal`=有异常；`ok`=无异常；`unknown`=这次判据没取到（标题里会说明，**仍不是空返回**） |
| `count` | 命中判据的条数；`count=0` 即 `status=ok`；`unknown` 时为 `null` |
| `title` | **直接展示这一句就行**，例如「今天有 13 个项目在县公司财务部审核节点积压超90天」「今天无项目逾期」 |
| `elapsed_ms` | 本次耗时（实测 5–10 秒） |

### 4 个定时技能

| skill_id | 技能 | 触发账号 | 范围 | 标题大概长这样 |
|---|---|---|---|---|
| `approval-role` | 各层级审批 | `xgscwb001`（县公司财务部） | 国网随县供电公司 | 今天有 N 个项目在本节点积压超 90 天 |
| `risk-control` | 风险预控 | `sgscwb`（市公司财务部） | 全市 | 今天有 N 笔申请资金明显不合理 |
| `flow-monitor` | 项目流程实时监控 | `sz002`（文峰所所长） | 文峰供电所 | 今天有 N 个项目逾期未处理 |
| `progress-alert` | 项目执行进度异常提醒 | `sz009`（均川所所长） | 均川供电所 | 今天有 N 个项目执行进度异常 |

### 调用示例

```bash
curl -s -X POST http://47.121.183.81:8200/api/skill/title \
  -H "Content-Type: application/json" \
  -d '{"skill_id":"approval-role","account":"xgscwb001"}' --max-time 120
```

```python
import requests
r = requests.post("http://47.121.183.81:8200/api/skill/title",
                  json={"skill_id": "flow-monitor", "account": "sz002"}, timeout=120)
d = r.json()
print(d["status"], d["title"])       # ok / abnormal，标题直接展示
```

## 三、常规问答：POST /api/ask

请求与原来一致，**新增三个返回字段**。

```json
{ "question": "今天有没有项目逾期", "session_id": "s_xxx", "uid": "sz002", "history_turns": 5 }
```

| 返回字段 | 说明 |
|---|---|
| `answer` | 回答正文（纯文本） |
| `qtype` | **新增**：`查数` 或 `分析`（服务自动分流，不用你们传） |
| `analysis_rules_hit` | **新增**：分析题命中的判断规则条数（0 = 没用规则，属查数类） |
| `page_html` | **新增**：分析题的「分析页面」—— 一整页可直接渲染的 HTML（含 ECharts 图表）；查数类为空字符串 |
| `session_id` / `qa_id` | 会话与本次问答的 ID，做多轮和评价要用 |

**两条流程的差别**（你们不用管，只有影响耗时）：

- **查数**（「线损率是多少」「有多少个项目」）→ 取数即答，实测约 6 秒。
- **分析**（「今天有没有项目逾期」「为什么比去年高」）→ 先取「分析规则」当判断标准再作答，
  并**再单独调一次模型**生成 `page_html`。实测分析约 10–25 秒，生成页面约 20–30 秒，
  **两者在同一次响应里返回**（不需要你们再调一次接口）。

前端拿到 `page_html` 直接内联展示即可（不要用 iframe 的 sandbox 限制脚本，页面靠 CDN 的
ECharts/Tailwind 渲染，需要能访问公网 CDN）。

## 四、定时标题之后，明细问题怎么接

定时任务只拿标题（一句话）。要明细时，把该技能预设的问题**逐个**丢给 `/api/ask`，
**共用同一个 `session_id`** —— 这样多轮之间会沿用上一轮的时间与地点口径，等于「一个会话里连问几问」。

```python
sid = "s_" + uuid.uuid4().hex          # 一场会话
for q in ["我这个节点上现在有多少待审批的项目？卡得最久的是哪几个、卡了多少天？",
          "有没有该到我这儿、却没到我手里的单（遗漏）？",
          "今天我先办哪几张？"]:
    r = requests.post(BASE + "/api/ask",
                      json={"question": q, "session_id": sid, "uid": "xgscwb001", "history_turns": 5},
                      timeout=180).json()
    print(r["qtype"], r["answer"][:50])
    # 需要的话：r["page_html"] 是这一问的分析页面
```

## 五、边界与注意

1. **服务无鉴权**，谁都能调。请只在可控网络里使用。
2. 定时接口 `elapsed_ms` 实测 5–10 秒，请把上游超时设到 **120 秒**以上。
3. `status:"unknown"` 只表示这一轮判据没取到，**不是**「无异常」；展示时建议提示人工核对。
4. 分析页面的 HTML 由模型生成，**页面上不会出现库里没有的数字**（我们要求它只按上文内容作图）。
5. 单进程多线程，单次问答 5–50 秒，适合几个人用，不适合当高并发网关。
