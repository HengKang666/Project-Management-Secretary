# 知识库接口 · 对接说明（v1.4）

> **v1.4（2026-09-22）全接口体检后的错误码规范化**：① 传错参数**一律 400**（之前有几处会返 500
> 甚至直接掐断连接）；② 新增**全局异常兜底** —— 任何未预料的异常都回 500 JSON 并记日志
> （以前客户端只看到"空响应"，无从排查）；③ 静态页面文件缺失返 404（不再抛异常）。
> 详见第七节的错误码表（新增 500 行）。**对正确调用的客户端零影响。**

> **v1.3（2026-09-22）三件事：① 单库模式（服务端只暴露一个知识库）；
> ② 异步上传（`?async=1`，接口立刻返回任务号）；③ 上传时按内容识别文件类型。见第十二节。**

> **v1.2（2026-09-22）新增「文件预览」：上传时自动留一份本地副本并抽出按页 HTML，
> 前端可直接渲染。见第十一节。**（云端与检索侧接口没变。）

> 本文只讲**知识库**这一组接口，是《接口对接说明.md》（智能问数）的**姊妹篇**，两者互不影响。
> 服务地址与问数服务**同一个**：本机 `http://127.0.0.1:8200`，生产 `http://47.121.183.81:8200`
> （**部署与运维**见第十节；本文示例统一用 `127.0.0.1`，是因为它们都在服务器本机执行 ——
> 换成 `47.121.183.81` 结果完全一样）。

## 一、这是什么

把阿里云百炼（Model Studio）的**知识库管理**能力接进了本服务，共 **5 个操作 + 1 个自检**：

| 想做什么 | 接口 | 谁用 |
|---|---|---|
| 看有哪些知识库 | `GET /api/kb/indices` | 同事（前端页）|
| 看某个知识库的详情 | `GET /api/kb/indices/{index_id}` | 同事（前端页）|
| 看知识库里有哪些文档 | `GET /api/kb/indices/{index_id}/documents` | 同事（前端页）|
| 传一份文档进知识库 | `POST /api/kb/indices/{index_id}/documents` | 同事（前端页）|
| 从知识库里删掉一份文档 | `DELETE /api/kb/indices/{index_id}/documents/{file_id}` | 同事（前端页）|
| 检查云端配好没有 | `GET /api/kb/health` | 排障用 |
| **看某个文件的抽取状态 / 页数** | **`GET /api/kb/files/{file_id}`** | **同事（预览）** |
| **取某一页的富文本（HTML）** | **`GET /api/kb/files/{file_id}/text?page=N`** | **同事（预览）** |
| **下载原文件** | **`GET /api/kb/files/{file_id}/download`** | **同事（下载）** |

**两个关键前提，先说清：**

1. **知识库在阿里云那边，服务只是"遥控器"。** 上传的文档实际存在阿里云百炼，本服务不保存任何知识库内容。删掉了本地也找不回来。
2. **知识库是"附属能力"，坏了不影响问数。** 凭据没配 / SDK 没装 / 连不上云端，只会让 `/api/kb/**` 返回 **503** 并说明原因；`/api/ask` 问答一切照常。

## 二、基本信息

| 项 | 值 |
|---|---|
| 服务地址 | `http://<服务器IP>:8200`（本机 `http://127.0.0.1:8200`）|
| 编码 | UTF-8 |
| 鉴权 | **无需 token**；阿里云 AK/SK 只存在服务端 `.env`，**前端拿不到** |
| 前端页面 | `http://<服务器IP>:8200/kb`（知识库控制台，给同事直接点着用）|
| 数据格式 | 请求/响应均为 `application/json`（上传除外）|

### 服务端要先配好 4 个值

在项目根目录的 `.env` 里（键名见 `.env.example`）：

```ini
ALIBABA_CLOUD_ACCESS_KEY_ID=          # RAM 用户的 AccessKey
ALIBABA_CLOUD_ACCESS_KEY_SECRET=
WORKSPACE_ID=llm-3z7uw7fwz0vexxxx     # 业务空间 ID，**必须以 llm- 开头**
DEFAULT_INDEX_ID=o95n15b77j           # 默认知识库 ID（可选，配了就能省略路径里的 index_id）
```

> ⚠️ **`.env` 只在服务启动时读一次，改完必须重启服务。**
> 配好之后跑一次 `GET /api/kb/health`，它会直接告诉你卡在哪一层（见第七节）。

## 三、★ 最容易卡住的地方：两套权限体系

**阿里云 RAM 权限 ≠ 百炼业务空间成员，是两套完全独立的体系。**

| 体系 | 在哪配 | 管什么 |
|---|---|---|
| RAM 权限 | 阿里云控制台 → 访问控制 | 能不能调开放接口（`AliyunBailianDataFullAccess`）|
| **业务空间成员** | **百炼控制台 → 左下角【权限管理】→【用户管理】** | 能不能访问**某个具体业务空间** |

**只配了前者、没配后者的典型症状（极具迷惑性）：**

```json
// GET /api/kb/health 返回 200，但……
{"ok": false, "credential_ok": true, "workspace_access_ok": false,
 "index_total": 0, "diagnosis": "workspace_forbidden",
 "hint": "..."}
```

紧接着所有写操作报 `NOT AUTHORIZED` / `Access denied: ... or the workspace does not exist.`

**为什么会这样**：`ListIndices` 是百炼里少数**不校验业务空间成员身份**的接口，
所以它会"成功"返回空列表，把人误导成"知识库 ID 填错了"。
`/api/kb/health` 特意用 `ListCategory` 做了第二次探针，才能把这两种情况分开。

**修复**：主账号登录百炼控制台 → 左下角【权限管理】→【用户管理】→【新增用户】→
类型选「RAM 用户」→ 选中子账号 → 保存并配置权限 → 勾选目标业务空间，角色「管理员」。

> 2025-08-06 起百炼收回了子账号的默认高级权限，必须显式赋权。
> 最快的二分定位法：临时换**主账号** AK/SK 试一次（官方明确主账号可直接调用、无须加入业务空间）——
> 通了就是子账号权限问题，不通就是 `WORKSPACE_ID` 填错了。

## 四、接口总览

| # | 方法 | 路径 | 说明 |
|---|---|---|---|
| 1 | GET | `/api/kb/health` | 分层自检：凭证是否有效 / 业务空间是否有权 |
| 2 | GET | `/api/kb/indices` | 知识库列表 |
| 3 | GET | `/api/kb/indices/{index_id}` | 知识库详情（配置 + 各状态文档数 + 存储监控）|
| 4 | GET | `/api/kb/indices/{index_id}/documents` | 知识库里的文档列表 |
| 5 | POST | `/api/kb/indices/{index_id}/documents` | 上传文档（multipart 或裸二进制）|
| 6 | DELETE | `/api/kb/indices/{index_id}/documents/{file_id}` | 删除知识库里的文档 |
| 7 | GET | `/api/kb/files/{file_id}` | **本地文件详情**（抽取状态 / 页数 / 有没有原文）|
| 8 | GET | `/api/kb/files/{file_id}/text?page=N` | **取某一页的 HTML 富文本**（预览主接口）|
| 9 | GET | `/api/kb/files/{file_id}/download` | **下载原文件** |
| 10 | GET | `/api/kb/uploads/{task_id}` | **异步上传任务状态**（v1.3 新增）|

> 7~9 这三个是**本地台账**接口（v1.2 新增）：**不依赖阿里云 SDK 与凭据**，
> 云端挂了、凭据没配，已存文件的预览照样能用。断句解释：前 6 个走云端，后 3 个走本地。

> `{index_id}` 可以**省略**：路径写成 `/api/kb/indices//documents` 不美观，
> 所以当知识库只有一个时，直接配 `.env` 的 `DEFAULT_INDEX_ID`，路径里仍传具体 ID 更清晰。

## 五、逐个接口

### 1. 连通性自检 `GET /api/kb/health`

排障**第一个该跑的接口**。不消耗配额、不产生数据。

**响应**

```json
{
  "ok": true,                       // 一站式结论：凭证+空间权都通
  "credential_ok": true,            // AK/SK 能通过鉴权
  "workspace_access_ok": true,      // 有该业务空间的访问权
  "workspace_id": "llm-3z7uw7fwz0vexxxx",
  "endpoint": "bailian.cn-beijing.aliyuncs.com",
  "index_total": 2,                 // 该业务空间下的知识库数量
  "indices": [ { "index_id": "...", "name": "..." } ],
  "diagnosis": "healthy",           // 见下表
  "hint": ""                        // 出问题时给下一步该做什么
}
```

`diagnosis` 取值对照：

| 值 | 含义 | 下一步 |
|---|---|---|
| `healthy` | 一切正常 | — |
| `no_indices` | 凭证/权限都对，但空间下没有知识库 | 去百炼控制台建一个 |
| `workspace_forbidden` | **没加入该业务空间** | 见第三节 |
| `credentials_invalid` | AK/SK 本身不对 | 检查是否复制完整、是否与账号一致 |
| `transient_error` | 云端临时故障 | 稍后重试 |

```bash
curl "http://127.0.0.1:8200/api/kb/health"
```

### 4. 知识库里的文档 `GET /api/kb/indices/{index_id}/documents`

**Query 参数**

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `status` | string | — | `FINISH` / `RUNNING` / `INSERT_ERROR` / `DELETED` / `PARSE_FAILED` / `DOC_PARSING` |
| `name` | string | — | 按文件名（**不含后缀**）过滤 |
| `name_like` | bool | false | `name` 是否按模糊匹配 |
| `page_number` | int | 1 | 页码 |
| `page_size` | int | 20 | 每页条数（1~100）|

**响应**

```json
{
  "total_count": 12,
  "page_number": 1,
  "page_size": 20,
  "documents": [
    {
      "file_id": "file_9a657325...",   // ★ 删除时要用它
      "name": "供电所名称对照表.pdf",
      "size": 204800,                   // 字节
      "document_type": "PDF",
      "status": "FINISH",               // FINISH=已可检索；RUNNING=索引构建中
      "code": "",
      "message": "",
      "gmt_modified": "2026-09-21 10:12:00",
      "category_id": "default"
    }
  ]
}
```

**状态含义（前端要用颜色区分）**

| status | 含义 | 用户该怎么做 |
|---|---|---|
| `FINISH` | 已导入，**可被检索** | 正常 |
| `RUNNING` | 索引构建中（异步） | 等，刷新即可；**别重复上传** |
| `INSERT_ERROR` | 导入失败（看 `message`）| 删除后重新上传 |
| `PARSE_FAILED` | 云端解析失败 | 检查文件是否损坏/加密 |
| `DOC_PARSING` | 正在解析 | 等 |

```bash
curl "http://127.0.0.1:8200/api/kb/indices/o95n15b77j/documents?status=FINISH&page_size=50"
```

### 5. 上传文档 `POST /api/kb/indices/{index_id}/documents`

**两种请求格式，任选其一。**

#### 方式 A：multipart/form-data（标准，Postman / curl -F / 网页表单）

字段名随意（服务端取**第一个带 `filename` 的字段**）：

```bash
curl -F "file=@./供电所名称对照表.pdf" \
     "http://127.0.0.1:8200/api/kb/indices/o95n15b77j/documents"
```

#### 方式 B：裸二进制 + `X-Filename` 头（前端 `fetch` 最省事）

```js
await fetch(`/api/kb/indices/${id}/documents`, {
  method: 'POST',
  headers: { 'X-Filename': encodeURIComponent(file.name) },  // ★ 中文名要 URL-encode
  body: file,                                                // 直接传 File 对象
});
```

> **为什么中文文件名要 `encodeURIComponent`**：HTTP 头在 Python 里按 latin-1 解码，
> 直接塞中文会乱码。服务端会 `unquote` 还原，所以两种写法（编码/不编码）都能用。

**Query 参数（都有合理默认，一般不用传）**

| 参数 | 默认 | 说明 |
|---|---|---|
| `wait_parse` | true | 是否等云端解析完成再提交索引。`false` 则只上传登记，**不提交索引** |
| `submit_index` | true | 是否提交索引任务（需 `wait_parse=true`）|
| `skip_if_exists` | true | 上传前按**文件名**查一次，同名就跳过（尽力而为的去重）|

**响应**

```json
{
  "file_id": "file_9a657325...",
  "job_id": "index_xxx",              // 索引任务 ID；未提交时为 null
  "name": "供电所名称对照表.pdf",
  "size": 204800,
  "md5": "9a657325...",
  "parse_status": "PARSE_SUCCESS",    // 等解析超时会返回 PARSING（不算失败）
  "index_submitted": true,
  "skipped": false,                   // true = 同名已存在，本次没上传
  "message": "已提交索引任务。索引在云端异步构建，高峰期可能耗时数小时；……"
}
```

**上传做了什么（5 步链路，都是服务端自动完成）**

```
① ApplyFileUploadLease  申请上传租约（拿到预签名 URL）
② HTTP PUT              把文件二进制传到那个 URL
③ AddFile               登记到「数据连接」，拿到 fileId
④ DescribeFile 轮询     等云端解析完成（PARSE_SUCCESS）
⑤ SubmitIndexAddDocumentsJob  提交索引任务（★ 异步，可能耗时数小时）
```

**注意**

- 单文件 **1B ~ 100MB**。
- 第 ①⑤ 步的接口**都不幂等**：同一个文件重复提交会产生重复文档/重复切片。
  所以服务端做了同名检查（`skip_if_exists`），**但前端仍应防连点**。
- 返回 `skipped:true` 时表示知识库里已有同名文档，`file_id` 是**已有那份**的 ID。
- **索引是异步的**：返回 `index_submitted:true` 只是"任务交出去了"，
  要刷新文档列表看到 `FINISH` 才算真正可检索。

### 6. 删除知识库文档 `DELETE /api/kb/indices/{index_id}/documents/{file_id}`

```bash
curl -X DELETE "http://127.0.0.1:8200/api/kb/indices/o95n15b77j/documents/file_9a657325..."
```

**响应**

```json
{ "deleted": ["file_9a657325..."], "requested": "file_9a657325...",
  "note": "只删了知识库里的这份文档；「数据连接」里的源文件仍在，要彻底清理请到百炼控制台处理。" }
```

**三条规则，必须知道：**

1. **只有 `FINISH` / `INSERT_ERROR` 状态的文档能删**。`RUNNING`（索引构建中）删不掉，会报错。
2. **删除不可逆**，且**不会删除「数据连接」里的源文件**（那是另一个层）。
3. 云端**没有"更新文档"语义**：改了内容只能**先删再重传**。

## 六、同事怎么用（前端页面）

**打开 `http://<服务器IP>:8200/kb`**，页面上四块，对应上面 4 个操作：

| 页面区块 | 对应接口 | 怎么操作 |
|---|---|---|
| ① 查看知识库 | `GET /api/kb/indices` | 点「刷新列表」。点行里的「选用」会把该 ID 填到下面三个输入框 |
| ② 知识库详情 | `GET /api/kb/indices/{id}` | 填 ID 点「查看详情」，看文档数与各状态统计 |
| ③ 知识库里的文档 | `GET .../documents` | 填 ID、可选状态，点「刷新文档」；每条右侧有「删除」 |
| ④ 上传文档 | `POST .../documents` | 填 ID、选文件、点「上传」；上传完自动刷新文档列表 |
| （顶部）连通性自检 | `GET /api/kb/health` | 点「连通性自检」，右上角状态灯变绿/红 |

页面**打开时会自动做一次自检**，所以"没配凭据 / 权限不对"一眼就能看见，不用等点了上传才发现。

> **监听地址取决于"怎么起的"，不是取决于 `.env`：**
>
> | 启动方式 | 监听 | 同事能否访问 |
> |---|---|---|
> | 直接 `python server.py` | `127.0.0.1` | **不能**，只有本机 |
> | `bash start.sh` / `start.sh -d` | `0.0.0.0` | 能（脚本里设了 `SECRETARY_HOST`）|
> | `sudo bash install_service.sh`（服务器上的方式）| `0.0.0.0` | 能（systemd 单元里设了）|
>
> 服务器上走的是第三种，所以同事直接访问 `http://47.121.183.81:8200/kb` 即可，
> **不需要改 `.env`**。真要改端口/监听地址，见第十节 10.4。

## 七、错误码对照

服务端会把云端错误**翻译成语义正确的 HTTP 状态码**（不会一律返 500）：

| 状态码 | 含义 | 典型原因 | 排查 |
|---|---|---|---|
| 200 | 成功 | — | — |
| 400 | 参数错 | 路径参数空、文件为空、超 100MB | 看响应里的 `error` |
| 403 | **鉴权/授权失败** | 没加入业务空间、AK/SK 不对、签名错 | **跑 `GET /api/kb/health`**，见第三节 |
| 404 | 找不到 | `index_id` / `file_id` 不存在 | 核对 ID；确认它属于当前业务空间 |
| 405 | 方法不支持 | 用错 HTTP 方法 | 看第四节 |
| 429 | 被限流 | 调用太频繁（如 `GetIndexJobStatus` 限 20 次/分）| 降低轮询频率，稍后重试 |
| 502 | **云端故障** | 百炼侧异常 | 稍后重试 |
| 503 | **本地没配好** | 缺 `.env` 凭据 / SDK 未安装 | 响应里直接写明了缺什么 |
| 504 | 调用云端超时 | 网络慢 / 云端卡 | 重试 |
| **500** | **服务内部错误** | 服务端自己出的问题（**不是**你传错了）| 把响应里的 `error` 全文给我们。2026-09-22 起**所有未预料的异常都会兜成 500**，不会再出现"连接被掐断、只看到空响应" |

> ★ **400 与 500 要分清**：400 是"调用方传错"（改请求即可），500 是"服务端的锅"（找我们）。
> 体检时发现有几处传错参数会返 500（如 `qa_id` 传字符串、`limit` 传字母），已统一改成 400 ——
> **不会再让排查方向跑偏**。

**响应体两种形态都可能有，前端要都能认：**

```json
// A. 云端业务错误（HTTP 200 或 4xx，错误在 body）
{ "code": "Index.NotFound", "message": "……", "hint": "……", "retryable": false }

// B. 本地/参数错误
{ "error": "知识库未配置：缺少 XXX。请在项目根目录 .env 里补齐……" }
```

## 八、注意事项（踩过的坑）

1. **提交类接口不幂等** —— `ApplyFileUploadLease` / `SubmitIndexAddDocumentsJob` 重复调用会产生重复数据。前端要防连点。
2. **索引构建是异步的** —— "索引构建中"（`RUNNING`）是**正常状态**，高峰期可能耗时数小时；小文件通常几分钟到几十分钟。**不要因为看着没动静就重复提交。**
3. **删除有状态门槛** —— 只有 `FINISH` / `INSERT_ERROR` 能删。
4. **云端没有更新语义** —— 改文档只能"先删再传"，用 MD5 判断是否真的变了。
5. **只支持华北2（北京）** —— 中国站知识库功能仅该地域提供，接入点固定 `bailian.cn-beijing.aliyuncs.com`。
6. **`.env` 只在启动时读一次** —— 改完凭据必须重启服务。
7. **`WORKSPACE_ID` 与 `INDEX_ID` 别填反** —— 前者必须 `llm-` 开头。
8. **AK/SK 永远不下发前端** —— 所有调用都经过本服务中转。

```python
INDEX = "o95n15b77j"

print("file_id =", r["file_id"], "| 索引任务 =", r["job_id"])

# 3) 轮询文档状态直到 FINISH（索引是异步的）
for _ in range(60):

        break
```

### 10.7 ★ 安全：知识库这组是**写接口**

**问数接口没鉴权只是"被白嫖查询"（数据库只读，风险可控）。
但 `/api/kb/**` 能传文档、删文档 —— 挂到公网 8200，任何能访问这个 IP 的人
都能往百炼知识库里塞文件、把文件删掉**，既污染知识库、又烧配额
（`ApplyFileUploadLease` / `SubmitIndexAddDocumentsJob` 都不幂等，重复调用会造重复切片）。

**至少选一项做：**

- **推荐**：云控制台「安全组」把 8200 入方向**限制到公司出口 IP 段**（不用改代码）
- 或系统防火墙限定来源网段：
  ```bash
  firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="<公司出口网段>/24" port port="8200" protocol="tcp" accept'
  firewall-cmd --reload
  ```
- 或给 `/api/kb/**` 加一层 token 校验（要改 `kb_api.py`）
- 或暂不向外发布 `/kb` 页面地址

> AK/SK 本身是安全的：只存在服务端 `.env`，**所有调用都经本服务中转，前端拿不到**。

### 10.8 边界与容量

- 单文件 **1B ~ 100MB**；服务是**单进程多线程**（Python 标准库 `http.server`），
  适合几个人用，**不适合当高并发网关**。
- 服务**没有登录校验**，也**没有限流** —— 对外发布务必配合 10.7。
- 索引构建是**云端异步**的，高峰期可能耗时数小时，与本地部署无关，重启服务不影响云端任务。

### 10.9 ★ 两个「知识库」不要混：**本页管的是「管理面」，问数用的是「检索面」**

系统里其实牵着**两组互不相通**的知识库配置，最容易犯的错是：
**在 `/kb` 页面把文档传进了 A 库，然后发现问数答话一点没变。**

| | **管理面（本页这组接口）** | **检索面（问数/补全在用的）** |
|---|---|---|
| 谁在用 | `/api/kb/**`、`/kb` 页面 | 补全 `agent.complete_question()`、问答里的 `kb_search` 工具 |
| 读哪个配置 | `.env` 的 `WORKSPACE_ID` + **`DEFAULT_INDEX_ID`** | `config.py` 的 **`KB_AGENT_ID`（检索服务）+ `KB_IDS`（限定库）** |
| 当前值 | `DEFAULT_INDEX_ID=razubo7dra`（个人知识库）| `KB_AGENT_ID=aid-72fa8…`，`KB_IDS=r57xtq9ypm,razubo7dra`（两个库都检索）|
| 干什么 | 列出/上传/删除**云端文档** | 按语义检出**文档切片**塞给模型 |
| 走哪条链路 | 阿里云百炼**开放接口**（AK/SK 签名）| maas **知识检索服务**（用 `LLM_API_KEY` 作 Bearer）|

**⇒ 现在这个配置是"对齐"的**：管理面默认库（`razubo7dra`）**也在检索范围内**，
所以在 `/kb` 页面上传文档，检索是能看到的（不像以前传进 `igjhr8giyb` 那样石沉大海）。

> 注意：`razubo7dra` 是通过**把库里加进原有检索服务 `aid-72fa8…` 的绑定范围**实现的（2026-09-22，控制台操作，
> 没改代码）。所以"管理面默认库 ⊆ 检索面范围"这条要保持住 —— 以后再把 `DEFAULT_INDEX_ID` 换成别的库时，
> 记得同样先在控制台把它加进 `aid-72fa8…` 的绑定范围，否则就成了"传了但搜不到"。

### 10.10 换检索知识库：改配置之前，先在控制台过「授权」这一关

**实测（2026-09-21 / 2026-09-22 两次，线上真实调用）：**

```
【加库前】检索服务 aid-72fa… + r57xtq9ypm   → ✅ total=3  《预算与成效分析AI业务知识库》×2、《测试1》
         检索服务 aid-72fa… + razubo7dra   → ❌ 401 Unauthorized   ← 库没在绑定范围里
         检索服务 aid-72fa… + uxht00z9ey   → ❌ 401 Unauthorized
         检索服务 aid-72fa… + igjhr8giyb   → ❌ 401 Unauthorized

【加库后】检索服务 aid-72fa… + r57xtq9ypm            → ✅ total=5
         检索服务 aid-72fa… + razubo7dra            → ✅ total=5
         检索服务 aid-72fa… + r57xtq9ypm,razubo7dra → ✅ total=5
```

**结论：`KB_IDS` 只是「在检索服务已授权的范围内再收窄」，不是「选库」。**
检索服务（`aid-…`）在百炼控制台有自己的**绑定范围**，超出范围一律 401。

> ⚠️ **两次实测的返回条数不一样（3 → 5），说明这段时间云端索引/文档有变动。**
> 所以"某个库能检索出几条"这种结论**有过期时间**，要用的时候重新跑一次探针，别照抄旧数字。

**换库的三步（缺一不可）：**

| 步 | 在哪做 | 做什么 |
|---|---|---|
| ① | 百炼控制台 → 知识检索服务 | 把目标知识库**加进检索服务的绑定范围**（或新建一个检索服务只绑它，拿到新的 `aid-…`）|
| ② | 百炼控制台 → 权限管理 | 确认当前 AK/SK（或 `LLM_API_KEY` 对应的账号）对该库**有读权限** |
| ③ | **服务端配置** | 改 `SECRETARY_KB_AGENT`（换服务）和/或 `SECRETARY_KB_IDS`（换/加库），重启服务 |

**第 ③ 步怎么改（★ 这里有个坑）：**

⚠️ **`SECRETARY_KB_AGENT` / `SECRETARY_KB_IDS` 写在项目 `.env` 里是不生效的！**
`config.py` 用的是 `os.environ.get()`，而 `.env` 只被读进一个 `ENV` dict、**没有写回环境变量**
（同一坑也适用于 `SECRETARY_MODEL` / `SECRETARY_TABLES` / `SECRETARY_MAX_STEPS`）。
例外：`SECRETARY_LEXICON*` 和 4 个百炼键做了 `.env` 兜底，**那几个 `.env` 生效**。

所以只能走**真环境变量**（本项目采用的方式）：

```bash
# 方式 A：装成 systemd 服务时（install_service.sh 生成的单元里已带这一行，默认就是两个库）
sudo bash install_service.sh

# 方式 B：已经在跑的服务，临时改
sudo systemctl edit secretary      # 加下面两行
#   [Service]
#   Environment=SECRETARY_KB_IDS=r57xtq9ypm,razubo7dra
sudo systemctl daemon-reload && sudo systemctl restart secretary

# 方式 C：本地/临时调试
set SECRETARY_KB_IDS=r57xtq9ypm,razubo7dra && python -X utf8 server.py
```

**另一种更省事的换库方式**：不碰检索服务，直接把新文档**传进检索范围内的某个库**
（用 `/kb` 页面上传，该库已在绑定范围里，传完就能被检到）——
因为检索服务已经绑了它，传完就能被检到。

## 十一、文件预览（本地台账，v1.2 新增）

### 11.1 为什么要在本地存一份

阿里云百炼**只给文件元信息，不提供原文下载、也不能按页取文本** —— 光靠云端做不了预览。
所以本服务在上传时多做两件事：

```
① 原文件落到服务器磁盘   {KB_FILE_ROOT}/{index_id}/{md5}/{原文件名}
② 抽成「按页的 HTML 富文本」存库（agent_data 的 t_kb_file / t_kb_file_page）
```

**原文存磁盘、正文存数据库**，各司其职：

| 存什么 | 存哪 | 为什么 |
|---|---|---|
| 原文件二进制 | 服务器磁盘（默认 `<部署目录>/kb_files/`，可配 `SECRETARY_KB_FILES`）| 100MB 文件塞 MySQL BLOB 会拖慢备份/查询/迁移；内网化后本地磁盘也最合适 |
| 文件元信息（台账）| 表 `t_kb_file` | 要能按状态/上传人查、要能对账、要能标记抽取进度 |
| **按页正文（HTML）** | 表 `t_kb_file_page` | 要能按页取、将来要建全文索引、要能重抽 |

### 11.2 上传后发生什么（时序）

```
POST /api/kb/indices/{index_id}/documents
  ① 落本地磁盘（先做，因为云上传最长等 300 秒，字节只在我们手里过一次）
  ② 传云端（ApplyFileUploadLease → PUT → AddFile → 等解析 → 提交索引）
     └─ 失败 → 删掉刚落的本地文件（不留孤儿），接口报错
  ③ 记台账 + 投递异步抽取任务 → 接口返回（响应里多一个 local 字段）
后台线程
  ④ 抽 HTML 富文本 → 写 t_kb_file_page → 把 extract_status 改成 done
```

**★ 抽取是异步的**：大 PDF 要几十秒到几分钟，不能挂在 HTTP 请求里。
接口返回后前端**轮询** `GET /api/kb/files/{file_id}` 看 `extract_status`。

| extract_status | 含义 | 前端该怎么做 |
|---|---|---|
| `pending` | 排队中 | 稍后重试 |
| `extracting` | 正在抽 | 稍后重试（建议 2~5 秒一次） |
| **`done`** | 抽好了，`page_count` / `text_chars` 有值 | 调 `/text` 取正文 |
| `unsupported` | **这种文件抽不出文字**（图片 / 老式 .doc / 加密或扫描 PDF）| 显示"无预览，请下载原文件"，`extract_error` 里有原因 |
| `failed` | 抽取过程出错 | 同上，`extract_error` 里有原因 |
| `none` | **本地没有这个文件**（在百炼控制台直接传的）| 同上 |

> ⚠️ **控制台直接上传的文件没有预览。** 它的 `origin` 会是 `console`、`has_text=false`。
> 想让某个文件有预览，必须**通过本服务的上传接口**再传一次。

```bash
curl "http://127.0.0.1:8200/api/kb/files/file_9a657325..."
```

```json
{

  "file_name": "系统运维手册.docx",
  "file_ext": ".docx",
  "size_bytes": 39314,
  "md5": "f369d563948418103eea46ebfa9d48fd",
  "origin": "api",                      // api=本服务传的 / console=控制台传的
  "page_count": 1,
  "text_chars": 1348,
  "text_format": "html",

  "extract_error": null,

  "has_raw": true,                      // 能不能下载原文（origin=console 时为 false）
  "uploader": "PROV-FIN-001",
```

`file_id` 不在本地台账 → **404**，错误里会写明"可能是控制台直接传的"。

### 11.4 `GET /api/kb/files/{file_id}/text?page=N` —— 取富文本（★ 预览主接口）

| 参数 | 说明 |
|---|---|
| `page` | 页码，**从 1 开始**。不传 / 传 `0` / 传 `all` = **返回全部页** |

```bash
curl "http://127.0.0.1:8200/api/kb/files/file_9a657325.../text?page=1"
```

```json
{
  "file_id": "file_9a657325...",
  "file_name": "系统运维手册.docx",
  "text_format": "html",
  "extract_status": "done",
  "ready": true,                        // ★ false 时不要渲染，按 message 提示用户
  "page_count": 1,
  "page": 1,
  "returned": 1,
  "pages": [
    {
      "page_no": 1,
      "page_label": "第 1 节",
      "html": "<p>员工管理系统 运维手册（V1.3）</p><h1>1. 系统概述</h1><table>…</table>",
      "char_count": 1348
    }
  ],
  "note": "HTML 已做白名单清洗，可直接 innerHTML 渲染；页与页之间请按 page_no 顺序拼接展示。"
}
```

**前端怎么用：**

```js
const r = await (await fetch(`/api/kb/files/${fileId}/text?page=1`)).json();
if (r.ready) {
  box.innerHTML = r.pages.map(p => `<section><h4>${p.page_label}</h4>${p.html}</section>`).join('');
} else {
  box.textContent = r.message;   // "正在提取…" 或 "无法预览，请下载原文件"
}

// 页面打开时若还没抽完，轮询详情接口
// while (detail.extract_status === 'pending' || detail.extract_status === 'extracting') 等 2 秒重试
```

**三条要注意的：**

1. **`html` 已经过白名单清洗**（`<script>` / `onerror=` / `javascript:` 全部被剥掉），
   因此可以直接 `innerHTML`。但**不要**再往里插用户输入，也不要放开它去做任意 HTML 编辑。
2. **"全部页"模式有体积保护**：累计超过 2MB 会截断，响应里 `truncated: true`。
   正常文档远不会触发；真触发就改成逐页取。
3. 页码越界（`page` 大于 `page_count`）→ **404**，错误里会写明"该文件共 N 页"。

### 11.5 `GET /api/kb/files/{file_id}/download` —— 下载原文件

浏览器直接打开即可（`Content-Disposition` 已按 RFC 5987 编码，**中文文件名不会乱码**）：

```bash
curl -OJ "http://127.0.0.1:8200/api/kb/files/file_9a657325.../download"
```

- 只有 `has_raw=true`（即通过本服务上传）的才有原文；控制台传的 → **404**
- 响应按 64KB 分块流式发出，大文件不占内存

### 11.6 支持的格式与「天然分页」规则

| 格式 | 分页单位 | 备注 |
|---|---|---|
| **PDF** | **每页一页** | 有文字层就能抽；**扫描件不行**（需 OCR，目前不支持）|
| **DOCX** | 按段落切块（每块约 2000 字）| 表格会输出成真正的 `<table>` |
| **XLSX** | **每个 sheet 一页** | 超过 3000 行会截断并注明 |
| **PPTX** | **每张 slide 一页** | 需装 `python-pptx` |
| **MD / TXT / CSV / JSON / SQL** 等纯文本 | 按固定行数切块 | 自动识别 UTF-8 / GBK |
| 图片（png/jpg…）、老式 `.doc` / `.xls` / `.ppt`、压缩包 | **不支持** | 上传仍会成功，只是 `extract_status=unsupported`，`extract_error` 写明该怎么办 |

> **已知局限**：PDF 按页切会让**跨页的表格断开**（表头在上一页时，下一页只剩数据行）。
> 按页顺序连续阅读不受影响；如果业务上很在意，需要后续在拼接时补表头。

### 11.7 运维：`/health` 多了 `kb_files` 字段

```json
{"ok": true, "name_fix": true, "qa_log": true, "kb": true,
 "kb_files": true, "kb_files_source": "mysql:agent_data"}
```

| 字段 | `false` 时说明什么 | 怎么修 |
|---|---|---|
| `kb_files` | 台账表没建 / 连不上 → 上传照旧成功，但**没有本地副本、没有预览** | `python tools/apply_kb_file_schema.py` 建表 |

抽取能力（哪个格式真的能用）可以这样一次性看：

```bash
cd /root/agentkownlg/deploy_server/secretary
python3 -X utf8 -c "import text_extract; print(text_extract.status())"
# {'ready': ['pdf','docx','xlsx',...], 'missing': ['pptx(缺 pptx)'], 'available': true}
```

> 「重启后没抽完的文件」不会丢：服务启动时会扫台账里 `pending/extracting` 的行**自动重新排队**，
> 启动日志里有一行 `[启动] 文件台账就绪（… 本次恢复 N 个待抽取）`。

## 十二、v1.3 三项改动

### 12.1 ★ 单库模式：服务端只暴露一个知识库

**默认开启**（`config.KB_SINGLE_INDEX`；要恢复旧行为设 `SECRETARY_KB_SINGLE=0`）。

| 行为 | 单库模式下 |
|---|---|
| `GET /api/kb/indices` | **只返回 `DEFAULT_INDEX_ID` 那一个**（`total_count=1`、`locked=true`），不再下发"还有哪些库" |
| 路径 / 参数里的 `index_id` | **一律被忽略**，永远用 `DEFAULT_INDEX_ID`（传了别的值会打一行日志留痕） |
| `GET .../documents` 响应 | 多两个字段：`index_id`（实际用的库）、`locked`（是否单库模式） |
| `GET /api/kb/indices` 响应 | 多 `locked` / `index_id` / `note` |

```bash
curl "http://127.0.0.1:8200/api/kb/indices"
# {"total_count":1,"locked":true,"index_id":"razubo7dra",
#  "note":"服务处于单库模式（SECRETARY_KB_SINGLE=1），只暴露这一个知识库。",
#  "indices":[{"index_id":"razubo7dra","name":"个人知识库",...}]}

# 就算你硬指定别的库，也会被忽略（实际仍是 razubo7dra）：
curl "http://127.0.0.1:8200/api/kb/indices/6k0y9t78rj/documents"
# {"index_id":"razubo7dra","locked":true,"documents":[...]}
```

> ⚠️ **为什么必须在服务端做**：前端不显示只是"看不见"，只要接口还接受 `index_id`，
> 换个 ID 就能操作别的库 —— 那不叫隔离，叫障眼法。所以这里是**服务端强制**。

### 12.2 异步上传（推荐用这个）

同步上传时 HTTP 请求要一直挂着等云端完成（最长 300 秒），而这期间前端连 `file_id` 都拿不到，
**等于什么都做不了**。异步模式把这条链路搬到后台：

```
① POST /api/kb/indices/{index_id}/documents?async=1   （multipart 或裸二进制都行）
   → **毫秒级**返回：
     {"task_id": "up_9124575ef18c458f9b3ebcd327d1755b",
      "status": "pending",
      "file_name": "unnamed.docx",
      "size_bytes": 16374,
      "status_url": "/api/kb/uploads/up_9124575ef18c458f9b3ebcd327d1755b",
      "note": "已收到文件并落入本地，正在后台上传；请轮询 status_url。..."}

② GET /api/kb/uploads/{task_id}                       轮询（建议 2 秒一次）
   → {"status": "pending"}     还没开始
   → {"status": "uploading"}   正在传云端
   → {"status": "done", "file_id": "file_afd4a088...", "elapsed_ms": 28089,
      "text_url": "/api/kb/files/file_afd4a088.../text", "detail_url": "..."}
   → {"status": "failed", "error": "..."}

③ 拿到 file_id 后，接着走第十一节的预览接口（/text 也在轮询，见 11.2）
```

**前端片段：**

```js
const r = await (await fetch(`/api/kb/indices/razubo7dra/documents?async=1`, {
  method: 'POST',
  headers: { 'X-Filename': encodeURIComponent(file.name) },
  body: file,
})).json();

// 立刻就能给用户反馈，不用等 300 秒
while (true) {
  await new Promise(s => setTimeout(s, 2000));
  const t = await (await fetch(r.status_url)).json();
  if (t.status === 'done')   { /* 用 t.file_id 去取预览 */ break; }
  if (t.status === 'failed') { alert('上传失败：' + t.error); break; }
}
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `async` | 看服务端 `SECRETARY_KB_ASYNC_DEFAULT`（默认 `0`=同步）| `1` 走异步并立刻返回；`0` 强制同步 |
| 其余参数 | 同同步模式 | `wait_parse` / `submit_index` / `skip_if_exists` / `uid` |

> ★ **默认仍是同步**（对现有前端零影响）。等你的前端接好轮询，把
> `SECRETARY_KB_ASYNC_DEFAULT=1` 写进 systemd 环境变量，就默认走异步了。

**三条要知道的：**

1. **任务落表**（`t_kb_upload_task`），所以服务重启后仍能查到历史任务。
2. **重启会把「上传中」的任务标成 `failed`，不会自动重试** —— 上传链路里的
   `ApplyFileUploadLease` / `SubmitIndexAddDocumentsJob` **都不幂等**，重试会造重复文档，
   而且我们无法判断上次传到哪一步了。宁可让用户重传一次。
3. 上传失败/同名跳过时，**本地那份副本会被清掉**（不留孤儿文件）。

### 12.3 按内容识别文件类型（避免抽出乱码）

文件名不再可信 —— 前端用 `fetch(url,{body:file})` 时如果漏了 `X-Filename`，
文件名就是空的；用户也可能把 docx 改名成 txt。

| 场景 | 处理 |
|---|---|
| 文件名没后缀 | **按内容嗅探**后补上（`%PDF`→`.pdf`；zip 里看 `word/`→`.docx`、`xl/`→`.xlsx`、`ppt/`→`.pptx`）|
| 后缀与内容矛盾（如 docx 叫成 `.txt`）| **以内容为准**（否则会把 zip 二进制当文本抽成几页乱码）|
| 真是二进制却叫 `.txt`（如 jpg）| 抽不了 → `extract_status=unsupported`，错误里写明"后缀与实际内容不符" |

### 12.4 `/health` 现在是六个能力字段

```json
{"ok": true, "model": "qwen3.8-max",
 "name_fix": true, "qa_log": true,
 "kb": true, "kb_source": "aliyun-bailian",
 "kb_files": true, "kb_files_source": "mysql:agent_data",
 "kb_upload": true, "kb_upload_source": "mysql:agent_data",
 "session_summary": true, "session_summary_source": "mysql:agent_data"}
```

| 新增字段 | `false` 说明什么 | 怎么修 |
|---|---|---|
| **`kb_upload`** | 上传任务表没建 → `?async=1` 会失败（同步上传不受影响）| `python tools/apply_kb_file_schema.py` |
| **`session_summary`** | L2 会话摘要**未启用**（开关关了）或摘要列不可用 | 看 `session_summary_reason`；开关是 `SECRETARY_SESSION_SUMMARY` |
