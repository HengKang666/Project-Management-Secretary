# 部署脚本使用说明（转给同事）

> 一键把本地仓库的代码更新到线上服务器，替代"打包 → 手工上传 → 手工重启"。
> **脚本在仓库里，不用单独找我要**：`tools/deploy_update.py`

## 一、你（执行部署的人）需要准备什么

| 需要什么 | 说明 |
|---|---|
| **仓库** | `git clone` 本项目（脚本必须放在仓库里跑，因为它按"仓库根目录"收集要上传的文件） |
| **Python 3.9+** | Windows 用 `py`，Linux/macOS 用 `python3` |
| **一个依赖** | `pip install paramiko` （只有它一个） |
| **SSH 密码** | **不在仓库里**（`.env` 被 gitignore）。找 Fred 单独要 |
| **能连服务器** | 目标机 `47.121.183.81:22`（root）。**注意：`.env.example` 里那个 `SERVER_HOST=47.121.127.9` 是废弃旧机，脚本已写死正确的机器** |

把 SSH 密码放两处之一即可：

```bash
# 方式 A（推荐，不落盘）：临时环境变量
set DEPLOY_SSH_PASS=你的密码          # Windows cmd/pwsh
export DEPLOY_SSH_PASS=你的密码       # Linux/macOS

# 方式 B：在仓库根目录建一个最小 .env，只放这一行
SERVER_SSH_PASSWORD=你的密码
```

> ⚠️ 别把服务器完整 `.env` 拷到本地又用 `--with-env` 推上去 —— 默认行为是**保留服务器上的 .env**，不要动它。

## 二、怎么跑（在仓库根目录）

```bash
# 1) 先看差异，只读、不写任何东西（养成习惯：先跑这个）
py -X utf8 tools/deploy_update.py --check            # Windows
python3 -X utf8 tools/deploy_update.py --check       # Linux/macOS

# 2) 正式更新
py -X utf8 tools/deploy_update.py

# 可选参数
#   --no-smoke   重启后不跑冒烟问答（想快一点）
#   --with-env   连本地 .env 一起推（**默认不推，一般不要用**）
```

## 三、脚本做了哪 7 步

```
[0/7] 列出待上传文件（用仓库 .gitignore 过滤，业务数据不会被传上去）
[1/7] 整目录备份当前线上版本 → /root/agentkownlg/deploy_server.bak.<时间戳>
[2/7] 上传到 _staging_deploy（不直接覆盖生产目录）
[3/7] 逐文件 md5 校验，任一不一致就中止（**不进重启**，避免半新版上线）
[4/7] 原子切换目录，**保留运行态** .env / output/ / kb_files/
[5/7] requirements.txt 变了才 pip install（阿里云镜像）
[6/7] 重启 systemd 服务 secretary + 分级自检：
        /health → /api/skills → /api/skill/title
[7/7] 冒烟问答（可用 --no-smoke 跳过）
      清理旧备份，只留最近 3 份
```

**任一步失败会自动回滚**：把备份换回来再重启，并打印回滚结果。

> ⚠️ 切换是「整目录替换」——**不在上传清单里的文件等于被删掉**。
> 所以 `output/`、`kb_files/`、`.env` 这三个不在仓库里的运行态，必须由脚本从旧目录搬过来。
> 其中 `kb_files/` 是知识库文件的**磁盘原文**：丢了台账还在、正文也还在，
> 但预览接口的 `has_raw` 会变 false、「下载原文」直接废掉（2026-09-23 真被这样弄没过一次）。
> 同理，仓库里挪过位置的文件（如 `deploy/` 下的 `start.sh` / `install_service.sh`）
> 必须写进脚本的上传清单，否则每部署一次就少一个。

## 四、出问题怎么办

| 现象 | 处理 |
|---|---|
| 想手工回滚 | 脚本每次成功都会打印回滚命令，照抄执行即可：`systemctl stop secretary && rm -rf <生产目录> && mv <备份> <生产目录> && systemctl start secretary` |
| `取不到 SSH 密码` | 没设 `DEPLOY_SSH_PASS`，且仓库根目录没有 `.env`/里面没 `SERVER_SSH_PASSWORD` |
| `ModuleNotFoundError: paramiko` | `pip install paramiko` |
| md5 校验不一致 | 脚本会中止，**线上还是旧版**，没被弄坏；重跑一次即可（多半是上传中断） |
| 依赖装了但服务起不来 | 看日志：`journalctl -u secretary -n 50 --no-pager` |
