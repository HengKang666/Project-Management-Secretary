# 知识库与历史对话 · 前端对接手册

> **这份文档是给前端同事的。** 把下面六件事一次讲完，每个接口都给**完整请求/响应示例**和
> **可直接粘贴的 JS 片段**：
>
> ① 怎么连上**指定那一个**知识库 → ② 怎么看知识库里的文件 → ③ 怎么预览文件内容
> → ④ 怎么上传 → ⑤ 怎么删除 → ⑥ 历史对话怎么**全部返回**
>
> **服务地址**：本机 `http://127.0.0.1:8200`　生产 `http://47.121.183.81:8200`
> **所有接口都无需鉴权**（也刻意不传 token），路径统一前缀 `/api`。
> **没有分页的接口就是全部返回** —— 本文所有"全部返回"的地方都直接说明，不用猜。

---

## 〇、六件事的接口一览

| # | 要做的事 | 接口 | 一句话 |
|---|---|---|---|
| 1 | 连上指定知识库 | `GET /api/kb/indices` | **服务端已经收口**，只会返回 `razubo7dra` 一个；你**什么都不用传** |
| 2 | 看文件列表 | `GET /api/kb/indices/{index_id}/documents` | 云端文档 + 本地台账合并后返回 |
| 3 | 预览文件 | `GET /api/kb/files/{file_id}` → `GET /api/kb/files/{file_id}/text?page=N` | 先看状态，再取**按页 HTML**，直接 `innerHTML` |
| 3b | 下载原文 | `GET /api/kb/files/{file_id}/download` | 二进制流，文件名已按 RFC 5987 编码 |
| 4 | 上传 | `POST /api/kb/indices/{index_id}/documents`（可选 `?async=1`）| 默认同步；异步会立刻返回任务号 |
| 4b | 查上传进度 | `GET /api/kb/uploads/{task_id}` | 只在异步模式用 |
| 5 | 删除 | `DELETE /api/kb/indices/{index_id}/documents/{file_id}` | 云端文档删掉；**本地原文默认保留** |
| 6 | 历史对话（全部返回）| `GET /api/sessions` / `GET /api/history` | **不传 `limit` 就是全部** |

> 排障第一步永远是 `GET /health`（看服务与各能力是否正常）和 `GET /api/kb/health`（看云端通不通）。

## 一、怎么连上"那一个"知识库

### 1.1 你不需要选库 —— 服务端已经收口

服务跑在**单库模式**（`SECRETARY_KB_SINGLE=1`，默认开）：

```
GET /api/kb/indices
```

```json
{
  "total_count": 1,
  "page_number": 1,
  "page_size": 1,
  "locked": true,
  "index_id": "razubo7dra",
  "note": "服务处于单库模式（SECRETARY_KB_SINGLE=1），只暴露这一个知识库。",
  "indices": [
    {
      "index_id": "razubo7dra",
      "name": "个人知识库",
      "description": "",
      "document_total": 3,
      "document_stats": "{\"RUNNING\":0,\"FINISH\":1,\"DELETED\":2}",
      "embedding_model": "text-embedding-v4",
      "source_type": "DATA_CENTER_FILE",
      "structure_type": "unstructured",
      "chunk_size": 500,
      "overlap_size": 50,
      "separator": "\\n\\n",
      "rerank_model": "",
      "rerank_min_score": 0,
      "enable_rewrite": true
    }
  ]
}
```

**要点：**

| 点 | 说明 |
|---|---|
| **`locked: true`** | 表示服务端强制单库。**前端不要再做"选用知识库"的下拉框**，也**不需要**把 `index_id` 传给任何人 |
| `index_id` | 就是你要用的那个库（目前 `razubo7dra`）。**建议从响应里读**，不要在前端硬编码 —— 服务端换库时你零改动 |
| ★ **路径里传别的库也不会生效** | 你自己拼一个 `/api/kb/indices/6k0y9t78rj/documents`，服务端会**忽略**它、仍用 `razubo7dra`（日志里留痕）。这是刻意的：**隔离必须在服务端做，前端隐藏只是障眼法** |
| `document_total` / `document_stats` | ⚠️ 这是**云端**统计，**含已删除的文档**（上例 `document_total=3`，实际可用只有 1 份 —— `DELETED` 占了 2）。**要以第 2 节的文档列表为准** |

### 1.2 建议的写法

```js
const BASE = 'http://47.121.183.81:8200';

// 启动时取一次，存起来；路径里带上它纯粹是为了"路径语义完整"，
// 就算不传/传错，服务端也会兜成同一个库。
let INDEX_ID = null;
async function initKb() {
  const r = await fetch(`${BASE}/api/kb/indices`);
  const d = await r.json();
  if (d.error) throw new Error(d.error);
  INDEX_ID = d.index_id;          // "razubo7dra"
  return d.indices[0];            // 库信息（名称、切片参数等）
}
```

## 二、怎么看知识库里的文件

```
GET /api/kb/indices/razubo7dra/documents
```

**查询参数：**

| 参数 | 默认 | 说明 |
|---|---|---|
| `page_number` | `1` | 第几页（**云端分页**，不是本服务的）|
| `page_size` | `20` | 每页几条 |
| `status` | | 按状态过滤，如 `FINISH` |
| `name` | | 按文件名过滤 |
| `name_like` | `0` | 传 `1` 时 `name` 变模糊匹配 |

**响应：**

```json
{
  "index_id": "razubo7dra",
  "locked": true,
  "page_number": 1,
  "page_size": 20,
  "total_count": 1,
  "documents": [
    {
      "file_id": "file_d7b69be3d7ba4c19818ee96c7c1cd5c6_13234964",
      "name": "预算与成效分析AI业务知识库",
      "size": 406,
      "document_type": "md",
      "status": "FINISH",
      "code": "FINISH",
      "message": "索引构建成功",
      "gmt_modified": 1789984409000,
      "category_id": "cate_ef7b2a18aa8649ff941456ffecf27523_13234964",

      "origin": "console",
      "extract_status": "none",
      "page_count": 0,
      "text_chars": 0,
      "has_text": false,
      "has_raw": false,
      "local_id": null,
      "detail_url": "/api/kb/files/file_d7b69b.../",
      "text_url": "/api/kb/files/file_d7b69b.../text"
    }
  ]
}
```

**外层字段（分页用）：**

| 字段 | 说明 |
|---|---|
| `index_id` / `locked` | 同上（单库模式下 `locked: true`）|
| `total_count` | **云端对本次查询的总条数**（做翻页用）。**实测：它不含已删除的文档** —— 当前库里 `document_total=3`（含 2 个 `DELETED`）而列表接口 `total_count=1` |
| `page_number` / `page_size` | 本次请求的页码与页大小 |

**每个字段干什么用 —— 前端最该看的是这四个：**

| 字段 | 说明 |
|---|---|
| **`file_id`** | **唯一标识**，预览/下载/删除都用它 |
| **`origin`** | `api` = **本服务上传的**（本地留了副本）；`console` = **在百炼控制台直接传的**（本地没副本）|
| **`has_text`** | `true` → 能预览内容（用 `text_url`）|
| **`has_raw`** | `true` → 能下载原文件（用 `download`）|
| `name` / `size` / `document_type` | 展示用（文件名 / 字节数 / 类型）|
| `gmt_modified` | **毫秒时间戳**，展示要 `new Date(v)` |
| `status` / `code` / `message` | 云端索引状态：`FINISH` 索引构建成功、`RUNNING` 构建中、`INSERT_ERROR` 插入失败、`PARSE_FAILED` 解析失败、`DOC_PARSING` 解析中。**只有 `FINISH` 和 `INSERT_ERROR` 能被删除** |
| `category_id` | 云端类目ID（当前用到默认类目，前端可忽略）|
| `extract_status` | 本地抽取状态，见第三节（`none` = 没有本地副本）|

**前端最容易踩的两个坑：**

1. **`origin=console` 的文件点不了预览** —— 它是在百炼控制台传的，我们本地没有原文。
   界面上应该**把预览/下载按钮置灰**并提示"该文件无本地副本，请在百炼控制台查看"。
2. **`status=RUNNING` 时不能删** —— 云端还在构建索引，删除会失败。**等 `FINISH` 再给删除按钮**。

```js
async function listDocuments(page = 1, pageSize = 20) {
  const u = new URL(`${BASE}/api/kb/indices/${INDEX_ID}/documents`);
  u.searchParams.set('page_number', page);
  u.searchParams.set('page_size', pageSize);
  const d = await (await fetch(u)).json();
  return d.documents.map(x => ({
    id: x.file_id,
    name: x.name,
    size: x.size,
    time: x.gmt_modified ? new Date(x.gmt_modified).toLocaleString() : '',
    status: x.status,
    canPreview: !!x.has_text,        // ← 预览按钮
    canDownload: !!x.has_raw,        // ← 下载按钮
    canDelete: x.status === 'FINISH' || x.status === 'INSERT_ERROR',
    reason: x.origin === 'console' ? '该文件在百炼控制台直接上传，无本地副本' : (x.message || '')
  }));
}
```

## 三、怎么预览文件内容

预览是**两步**：先问"能不能预览"，再取内容。

### 3.1 第一步：看状态

```
GET /api/kb/files/{file_id}
```

```json
{
  "file_id": "file_xxx",
  "index_id": "razubo7dra",
  "file_name": "系统运维手册.docx",
  "file_ext": ".docx",
  "size_bytes": 39314,
  "md5": "b6a1...",
  "origin": "api",
  "page_count": 4,
  "text_chars": 5120,
  "text_format": "html",
  "extract_status": "done",
  "extract_error": null,
  "extract_ms": 670,
  "has_text": true,
  "has_raw": true,
  "uploader": "PROV-FIN-001",
  "upload_time": "2026-09-22 17:10:03",
  "text_url": "/api/kb/files/file_xxx/text",
  "download_url": "/api/kb/files/file_xxx/download",
  "note": "HTML 已做白名单清洗，可直接 innerHTML 渲染；页与页之间请按 page_no 顺序拼接展示。"
}
```

**`extract_status` 决定你下一步做什么：**

| 值 | 含义 | 前端怎么做 |
|---|---|---|
| `pending` | 排队中 | **轮询**（1~2 秒一次），显示"正在提取…" |
| `extracting` | 正在抽取 | 同上 |
| **`done`** | **抽好了** | 调 `/text` 取内容 ✅ |
| `failed` | 抽取失败 | 显示 `extract_error`，提供"下载原文件"兜底 |
| `unsupported` | 这种格式不支持预览（如老式 `.doc`、图片）| 提示"无法预览，请下载"，**下载仍然可用** |
| `none` | 没有本地副本（控制台传的）| 置灰，提示去控制台看 |

> 抽取是**异步**的：一个 50MB 的 PDF 要几十秒到几分钟。**页面打开时轮询几次是正常做法**，
> 抽完就一直 `done`，不用每次都查。

### 3.2 第二步：取 HTML 内容（按页）

```
GET /api/kb/files/{file_id}/text?page=1
```

| 参数 | 说明 |
|---|---|
| `page` | 第几页（**从 1 开始**）。**不传 / 传 `0` / 传 `all` → 返回全部页** |

**响应（`ready=true` 时）：**

```json
{
  "file_id": "file_xxx",
  "file_name": "系统运维手册.docx",
  "text_format": "html",
  "extract_status": "done",
  "page_count": 4,
  "ready": true,
  "page": 1,
  "returned": 1,
  "note": "HTML 已做白名单清洗，可直接 innerHTML 渲染；页与页之间请按 page_no 顺序拼接展示。",
  "pages": [
    {
      "page_no": 1,
      "page_label": "第 1 页",
      "html": "<h1>系统运维手册</h1><p>本手册适用于…</p><table><tr><th>项目</th><th>值</th></tr>…</table>",
      "char_count": 1348
    }
  ]
}
```

**还没抽完 / 抽不了时，也是 200，但 `ready=false`：**

```json
{
  "ready": false,
  "pages": [],
  "returned": 0,
  "extract_status": "extracting",
  "message": "正在提取文件内容，请稍后重试（可轮询本接口或 /api/kb/files/file_xxx）"
}
```

**要点：**

| 点 | 说明 |
|---|---|
| ★ **`html` 已经过 XSS 白名单清洗** | `<script>` / `onerror` / `javascript:` 等已剥掉，**可以直接 `innerHTML`**，不用自己再洗一遍 |
| ★ **`page_label` 是你的小标题** | 不同文件类型含义不同：PDF = `第 3 页`、XLSX = `Sheet1`、PPTX = `Slide 2`、DOCX/TXT = `第 2 节`。直接当分页标题显示即可 |
| 天然分页规则 | **PDF 每页一页**；**XLSX 每个 sheet 一页**；**PPTX 每张 slide 一页**；**DOCX / MD / TXT 按字数切块** |
| `page` 越界 | 返 **404**，`{"error":"第 9 页不存在（该文件共 1 页）"}` |
| 取全部页的体积保护 | `page` 不传时若 HTML 合计超 **2MB** 会截断并置 `truncated: true` —— **大文件请逐页取** |
| 表格 | DOCX 的表格会转成真正的 `<table>`，不是纯文本 |

```js
async function previewFile(fileId, page = 0) {
  const u = new URL(`${BASE}/api/kb/files/${fileId}/text`);
  if (page) u.searchParams.set('page', page);
  const d = await (await fetch(u)).json();

  if (!d.ready) {
    // 还没抽完 / 格式不支持 —— 都能拿到一句人话说明
    return { ok: false, message: d.message || `无法预览（状态：${d.extract_status}）`, status: d.extract_status };
  }
  // ★ 直接 innerHTML；页与页按 page_no 顺序拼接
  const html = d.pages
    .sort((a, b) => a.page_no - b.page_no)
    .map(p => `<section data-page="${p.page_no}"><h4>${p.page_label}</h4>${p.html}</section>`)
    .join('');
  return { ok: true, html, pageCount: d.page_count, truncated: !!d.truncated };
}
```

### 3.3 下载原文件

```
GET /api/kb/files/{file_id}/download
```

- 返回**二进制流**，`Content-Type` 按后缀给（pdf / docx / xlsx / pptx / txt …）
- 文件名用 RFC 5987 编码：`Content-Disposition: attachment; filename*=UTF-8''%E7%B3%BB%E7%BB%9F...`
  —— 浏览器会正确显示中文名，**你不用管编码**
- 没有本地副本（`origin=console`）时返 **404**，`error` 里会说明原因

```js
// 方式一：直接让浏览器下载
window.open(`${BASE}/api/kb/files/${fileId}/download`);

// 方式二：拿 blob（要做预览/另存为时）
const blob = await (await fetch(`${BASE}/api/kb/files/${fileId}/download`)).blob();
const url = URL.createObjectURL(blob);
```

## 四、怎么上传

```
POST /api/kb/indices/razubo7dra/documents
```

### 4.1 两种 body 都支持

| 方式 | 怎么传 | 适合 |
|---|---|---|
| **multipart** | `curl -F file=@x.pdf` / `<form>` / `FormData` | 表单场景，最通用 |
| **裸二进制** | body 就是文件字节，文件名放 **`X-Filename`** 头 | `fetch(url, {body: file})` 最省事 |

> ⚠️ **`X-Filename` 里的中文必须 URL-encode**（HTTP 头按 latin-1 解析，直接放中文会乱码）。
> 用 `FormData` 就不用操心这个。

### 4.2 查询参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `async` | `0` | **`1` = 异步**，立刻返回任务号（见 4.4）|
| `uid` | | 上传人（**强烈建议传**，列表里能显示是谁传的）|
| `wait_parse` | `1` | 是否等云端解析完。同步模式下等，最长 300 秒 |
| `submit_index` | `1` | 是否自动提交索引构建 |
| `skip_if_exists` | `1` | 同名已存在就跳过（**不覆盖**）|

**文件名**：建议带后缀。**没后缀也没关系** —— 服务端会**按文件内容**识别类型并补对后缀
（否则 `docx` 会被云端当 `.txt` 解析成乱码）。

**大小上限**：**100MB**，超了返 400。

### 4.3 同步上传（默认）

```bash
curl -s -X POST -F "file=@系统运维手册.docx" \
  "http://47.121.183.81:8200/api/kb/indices/razubo7dra/documents?uid=PROV-FIN-001"
```

响应（在上传结果之外多一个 `local` 字段）：

```json
{
  "file_id": "file_xxx",
  "index_id": "razubo7dra",
  "skipped": false,
  "local": {
    "extract_status": "pending",
    "extract_status_url": "/api/kb/files/file_xxx",
    "text_url": "/api/kb/files/file_xxx/text",
    "note": "已落本地副本，正在后台抽取正文（抽完 /text 就能取 HTML）"
  }
}
```

> ⚠️ **同步模式会让请求挂住最长 300 秒**（云端要解析）。大文件建议用异步。

### 4.4 异步上传（推荐给大文件）

```bash
curl -s -X POST -F "file=@大文件.pdf" \
  "http://47.121.183.81:8200/api/kb/indices/razubo7dra/documents?async=1&uid=PROV-FIN-001"
```

**毫秒级返回**：

```json
{
  "task_id": "up_9124575e8c1b4f0e9a3d2c7b6f1e0a4d",
  "status": "pending",
  "file_name": "大文件.pdf",
  "size_bytes": 2891003,
  "md5": "3f2a...",
  "index_id": "razubo7dra",
  "status_url": "/api/kb/uploads/up_9124575e8c1b4f0e9a3d2c7b6f1e0a4d",
  "note": "已收到文件并落入本地，正在后台上传；请轮询 status_url。"
}
```

**轮询进度：**

```
GET /api/kb/uploads/{task_id}
```

```json
{
  "task_id": "up_9124575e...",
  "index_id": "razubo7dra",
  "file_name": "大文件.pdf",
  "size_bytes": 2891003,
  "md5": "3f2a...",
  "uploader": "PROV-FIN-001",
  "status": "done",
  "file_id": "file_xxx",
  "error": null,
  "elapsed_ms": 28089,
  "create_time": "2026-09-22 17:10:01",
  "update_time": "2026-09-22 17:10:29",
  "status_url": "/api/kb/uploads/up_9124575e...",
  "detail_url": "/api/kb/files/file_xxx",
  "text_url": "/api/kb/files/file_xxx/text"
}
```

> `file_id` / `detail_url` / `text_url` **只在 `done` 之后才有值**；前面几个状态它们是 `null`。

| `status` | 含义 | 前端 |
|---|---|---|
| `pending` | 排队中 | 显示"等待上传" |
| `uploading` | 正在传云端 | 显示"上传中…" |
| **`done`** | 成功，**`file_id` 可用** | 拿 `file_id` 去第 3 节预览 |
| `failed` | 失败，看 `error` | 显示原因，可让用户重试 |

> ⚠️ **服务重启会把"上传中"的任务标成 `failed`，且不会自动重试。**
> 原因：上传链路**不幂等**，重试会造重复文档。中断的任务仍在表里能查到，但要**人工重传**。

```js
// 前端封装：上传 + 轮询到终态
async function uploadFile(file, { uid } = {}) {
  const u = new URL(`${BASE}/api/kb/indices/${INDEX_ID}/documents`);
  u.searchParams.set('async', '1');
  if (uid) u.searchParams.set('uid', uid);
  // ⚠️ 文件名只能通过 body 传（multipart 的 filename 或 X-Filename 头），
  //    **没有** query 参数能覆盖它。

  const d = await (await fetch(u, {
    method: 'POST',
    headers: { 'X-Filename': encodeURIComponent(file.name) },  // 裸二进制方式
    body: file
  })).json();
  if (d.error) throw new Error(d.error);

  // 轮询
  while (true) {
    await new Promise(r => setTimeout(r, 2000));
    const t = await (await fetch(`${BASE}${d.status_url}`)).json();
    if (t.status === 'done')   return { ok: true,  fileId: t.file_id, elapsed: t.elapsed_ms };
    if (t.status === 'failed') return { ok: false, error: t.error };
  }
}
```

> 若你用 `FormData`（更简单、中文名不用编码）：把 `body: file` 换成
> `const fd = new FormData(); fd.append('file', file);` 然后 `body: fd`，**去掉 `X-Filename` 头**。

## 五、怎么删除

```
DELETE /api/kb/indices/razubo7dra/documents/{file_id}
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `drop_raw` | `0` | `0` = **保留磁盘原文**（删错了还有救）；`1` = 连本地原文一起删 |

```bash
curl -s -X DELETE "http://47.121.183.81:8200/api/kb/indices/razubo7dra/documents/file_xxx"
```

```json
{
  "deleted": ["file_xxx"],
  "requested": "file_xxx",
  "local_removed": 1,
  "local_raw_kept": true,
  "note": "只删了知识库里的这份文档；「数据连接」里的源文件仍在，要彻底清理请到百炼控制台处理。本地台账已软删但保留了磁盘原文（传 drop_raw=1 可一并删除）。"
}
```

**要点：**

| 点 | 说明 |
|---|---|
| ★ **云端删除不可逆** | 知识库里的切片会真的删掉，检索立刻不再命中。**前端务必二次确认** |
| **只有 `FINISH` / `INSERT_ERROR` 能删** | `RUNNING`（构建中）删除会失败 —— 用第 2 节的 `canDelete` 控制按钮 |
| **本地原文默认保留** | 想彻底清就传 `drop_raw=1` |
| 传了个不存在的 `file_id` | **200，`deleted: []`** —— 不算错误，前端按"没删到"提示即可 |

```js
async function deleteFile(fileId, alsoDropRaw = false) {
  if (!confirm('确定删除这份文档？知识库里的内容会立刻删掉，且不可恢复。')) return;
  const u = `${BASE}/api/kb/indices/${INDEX_ID}/documents/${fileId}` + (alsoDropRaw ? '?drop_raw=1' : '');
  const d = await (await fetch(u, { method: 'DELETE' })).json();
  return { ok: (d.deleted || []).length > 0, raw: d, note: d.note };
}
```

## 六、历史对话：怎么拿到"全部"

**核心结论：不传 `limit` 就是全部返回**，不需要你翻页，也没有"默认 20 条"这回事。

### 6.1 会话列表：`GET /api/sessions`

| 参数 | 说明 |
|---|---|
| `uid` | 只看某个用户的会话；**不传 = 全部用户** |
| `limit` | **不传 / 传 `0` = 全部**；传正整数 = 只要前 N 条 |
| `offset` | 跳过多少条（配合 `limit` 做分页）|

```json
{
  "total": 214,
  "returned": 214,
  "limit": 5000,
  "offset": 0,
  "truncated": false,
  "sessions": [
    {
      "session_id": "s_5f224f10aaed42a2bbcf45e2d0c504dd",
      "user_code": "PROV-FIN-001",
      "title": "环潭供电所上个月的线损率",
      "ai_model": "qwen3.8-max",
      "channel": "webapi",
      "client_ip": "127.0.0.1",
      "msg_count": 4,
      "status": 1,
      "create_time": "2026-09-20 15:37:41",
      "last_msg_at": "2026-09-20 15:37:51",
      "ended_at": null,
      "ask_count": 2,
      "gap_count": 0
    }
  ]
}
```

**外层四个分页字段 —— 前端判断"拿全了没有"就看这几个：**

| 字段 | 说明 |
|---|---|
| **`total`** | **符合条件的总数**（真实总数，不受 `limit` 影响）|
| `returned` | 本次实际返回条数（= `sessions` 长度）。**不传 `limit` 时 `total == returned`** |
| `limit` | 本次生效的上限；"全部返回"时等于防呆上限 **5000** |
| `truncated` | `true` = 数据超过防呆上限被截断了，**这时才需要用 `limit`+`offset` 取下一页** |

> ⚠️ **老的坑**：以前 `total` 填的是"本页条数"，前端看到 `total=20` 会以为库里总共只有 20 场。
> 2026-09-22 已修正。

### 6.2 某场会话的全部消息：`GET /api/history`

| 参数 | 必填 | 说明 |
|---|---|---|
| `session_id` | ✅ | 不存在返 **404** |
| `limit` | | **不传 / 传 `0` = 该会话全部消息** |
| `with_steps` | | 传 `1` 时每条 AI 回答多一个 `steps` 数组（调了什么工具、SQL、耗时）|

### 6.3 ★ "翻出历史对话继续聊"

**回传同一个 `session_id` 即可**，服务端会自动带上该会话的上下文：

```js
async function continueChat(sessionId, question) {
  const d = await (await fetch(`${BASE}/api/ask`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ question, session_id: sessionId })
  })).json();
  return d;   // d.session_id 仍是同一场；d.history_used 告诉你带上了几轮
}
```

响应里两个字段可以验证记忆是否生效：

| 字段 | 说明 |
|---|---|
| `history_used` | 本轮带上了几轮历史（**`0` 说明记忆没生效** —— 多半 `session_id` 传错）|
| `summary_used` | 更早轮次是否用了**会话摘要**（长会话才有）|
| `summary_skip` | 非 `null` 时写明"本轮为什么没用摘要"，排障先看它 |
| `history_injected` | 其中真正塞进提示的轮数（已摘要覆盖的不重复塞）|

> 会话聊长以后，更早的轮次会被自动压成一段摘要带入 —— 这是服务端行为，**前端不需要做任何事**。

## 七、错误码

| 码 | 含义 | 你要做什么 |
|---|---|---|
| **200** | 成功。**"查不到 / 不存在"也走 200**（如 `deleted: []`、`total: 0`）| 正常解析 body |
| **400** | **你传错了**：缺必填参数、类型不对、文件超 100MB、请求体不是合法 JSON | 改请求；原因在 `error` 字段 |
| **403** | 云端鉴权失败（知识库）| 让运维跑 `GET /api/kb/health` |
| **404** | 资源不存在：`session_id` 查不到、`file_id` 没有本地副本、页码越界 | 看 `error` 说明 |
| **405** | HTTP 方法用错 | 看第〇节的接口表 |
| **429** | 云端限流 | 降低轮询频率，稍后重试 |
| **500** | **服务端故障**（不是你的错）| 把 `error` 全文给我们 |
| **502 / 503 / 504** | 云端故障 / 本地没配好 / 云端超时 | 知识库相关；详见《知识库接口文档.md》第七节 |

> **400 与 500 一定要分清**：400 是"改请求就行"，500 是"找我们"。
> 2026-09-22 起服务端做了全面体检：**传错参数一律 400**，并且所有未预料的异常都会兜成
> **500 JSON + 服务端日志**（以前会直接掐断连接，客户端只看到"空响应"，无从排查）。

## 八、一条完整的端到端链路

```js
const BASE = 'http://47.121.183.81:8200';
let INDEX_ID;

// ① 连上那一个知识库
async function init() {
  const d = await (await fetch(`${BASE}/api/kb/indices`)).json();
  INDEX_ID = d.index_id;                    // razubo7dra
}

// ② 列出文件
async function refresh() {
  const d = await (await fetch(
    `${BASE}/api/kb/indices/${INDEX_ID}/documents?page_number=1&page_size=50`)).json();
  return d.documents;
}

// ③+④ 上传并等到抽好（可预览）
async function upload(file, uid) {
  const u = new URL(`${BASE}/api/kb/indices/${INDEX_ID}/documents`);
  u.searchParams.set('async', '1');
  u.searchParams.set('uid', uid);
  const fd = new FormData(); fd.append('file', file);          // 中文名不用编码
  const r = await (await fetch(u, { method: 'POST', body: fd })).json();
  if (r.error) throw new Error(r.error);

  // 轮询上传
  let fileId = null;
  for (let i = 0; i < 300; i++) {
    await new Promise(x => setTimeout(x, 2000));
    const t = await (await fetch(`${BASE}${r.status_url}`)).json();
    if (t.status === 'done')   { fileId = t.file_id; break; }
    if (t.status === 'failed') throw new Error(t.error);
  }
  if (!fileId) throw new Error('上传超时');

  // 轮询抽取
  for (let i = 0; i < 120; i++) {
    const f = await (await fetch(`${BASE}/api/kb/files/${fileId}`)).json();
    if (f.extract_status === 'done') return { fileId, ready: true };
    if (['failed', 'unsupported'].includes(f.extract_status))
      return { fileId, ready: false, reason: f.extract_error || f.extract_status };
    await new Promise(x => setTimeout(x, 2000));
  }
  return { fileId, ready: false, reason: '抽取超时' };
}

// ⑤ 预览
async function preview(fileId, page) {
  const u = new URL(`${BASE}/api/kb/files/${fileId}/text`);
  if (page) u.searchParams.set('page', page);
  const d = await (await fetch(u)).json();
  if (!d.ready) return { ok: false, message: d.message };
  document.querySelector('#viewer').innerHTML = d.pages
    .map(p => `<section><h4>${p.page_label}</h4>${p.html}</section>`).join('');
  return { ok: true, pageCount: d.page_count };
}

// ⑥ 删除
async function remove(fileId) {
  if (!confirm('删除后知识库立即不再命中该文档，且不可恢复。确认删除？')) return;
  await fetch(`${BASE}/api/kb/indices/${INDEX_ID}/documents/${fileId}`, { method: 'DELETE' });
}

// ⑦ 历史对话（全部）
async function history() {
  const d = await (await fetch(`${BASE}/api/sessions`)).json();   // 不传 limit = 全部
  return d.sessions;                                              // d.total === d.returned
}
```

## 九、排障速查

| 现象 | 先看这个 |
|---|---|
| 页面打开是一片空白 / 直接下载了页面 | 服务端已修（静态页不再被当附件）；若仍出现，确认访问的是 `/kb` 而不是 `/api/kb/...` |
| 上传成功但点不了预览 | 看 `extract_status`：`pending`/`extracting` 是还没抽完（等）；`none` 说明没本地副本；`unsupported` 是格式不支持（下载仍可用）|
| 列表里有文件但预览 404 | 那多半是 `origin=console`（控制台传的）—— 我们本地没留副本，**这是设计如此** |
| 上传返回 `skipped: true` | 同名文件已存在，服务端**不覆盖、也没留新副本**（同名字节不保证一致，覆盖会让 file_id 指错内容）。要替换请先删除旧文档 |
| 上传后云端一直 `RUNNING` | 云端索引是**异步**构建的，几分钟到几小时都正常，与我们无关 |
| 会话记忆好像没生效 | `/api/ask` 响应看 `history_used` 和 `summary_skip` —— **这两个字段就是为排障加的** |
| `total` 和 `returned` 对不上 | 只有超过防呆上限（5000）才会发生，此时 `truncated: true` |
| 知识库文件列表数量比 `document_total` 少 | `document_total` 含已删除文档，**以列表为准** |
