# 智能问数接口 · 对接说明

> 这份可以直接转给同事。

## 一、基本信息

| 项 | 值 |
|---|---|
| 地址 | **http://47.121.183.81:8200** |
| 端口 | **8200** |
| 协议 | HTTP。请求/响应都是 **UTF-8 的 JSON** |
| 鉴权 | **没有**（见下面「六、注意事项」第 3 条） |
| 单次耗时 | **5~30 秒**（要查库 + 调大模型），客户端超时请设 **≥ 90 秒** |
| 页面 | 浏览器打开 **http://47.121.183.81:8200/** 可直接对话试用 |

**接口一共就两个，先测这两个就够用：**

```bash
curl -s http://47.121.183.81:8200/health                      # 服务在不在
curl -s http://47.121.183.81:8200/ -o /dev/null -w "%{http_code}\n"   # 页面在不在，应返回 200
```

## 二、核心接口：问答

```
POST /api/ask
Content-Type: application/json
```

**请求体**

```json
{
  "question": "环潭供电所上个月的线损率"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `question` | ✅ | 用户的原话。**不用预处理**——错字、简称、没写时间地点都能直接问 |
| `model` | | 指定模型，不传用默认 `qwen3.8-max` |
| `max_steps` | | 工具调用步数上限，不传=不限 |
| `profile` | | 用户画像文本（可选，用于判断关注重点） |

**响应体**（`answer` 是你唯一需要关心的字段）

```json
{
  "answer": "2026年1-9月环潭供电所的台区线损率为3.65%。",
  "input_question": "环潭供电所的线损率",
  "fixed_question": "环潭供电所的线损率",
  "completed_question": "2026年1-9月环潭供电所的线损率是多少？",
  "completion_used": true,
  "name_fix_used": false,
  "scope": {
    "time": "2026年1-9月",
    "period_type": "yearToDate",
    "period_key": "202609",
    "time_is_default": true,
    "place": "环潭供电所",
    "place_is_default": false
  },
  "model": "qwen3.8-max",
  "elapsed_ms": 5662,
  "timings": {"namefix_ms": 0, "completion_ms": 1350, "loop_ms": 4310, "total_ms": 5662},
  "db_query_count": 1,
  "sql_query_count": 1,
  "kb_query_count": 0,
  "no_db_query": false,
  "unverified": false,
  "steps": 5
}
```

| 返回字段 | 说明 |
|---|---|
| **`answer`** | **回答正文，直接展示给用户** |
| `input_question` | 你传进来的原话（回显） |
| `fixed_question` | **纠错 + 补全时间地点**后的问题（可显示在"我理解为…"里） |
| `completed_question` | 再过一遍**问题补全规则**后的最终查询问题 |
| `completion_used` | 补全规则是否产出了不同内容（`false` = 你的原话已经够标准） |
| `name_fix_used` | 是否发生了错字纠正/名称归一 |
| `scope` | 识别出的统计范围（时间/地点），便于前端提示口径 |
| `model` | 实际使用的模型 |
| `elapsed_ms` | 总耗时（毫秒） |
| `timings` | 分阶段耗时：纠错 / 补全 / 主循环，排查慢在哪里用 |
| `db_query_count` / `sql_query_count` | 查了几次库 / 发了几条 SQL |
| `kb_query_count` | 查了几次知识库（口径库） |
| `no_db_query` | `true` = **一次库都没查**（说明是凭已有知识答的，需警惕） |
| `unverified` | `true` = 模型没查库就下结论，**已被拦下，这条回答不可信** |
| `steps` | 工具调用步数 |
| `user_profile` | 你传的 `profile` 原样回显（没传就是空串） |
| `trace` | 全过程明细（每步工具调用、SQL、耗时），调试用，正常展示不用管 |

> `no_db_query` 和 `unverified` 的区别：前者只是"没查库"这一事实，
> 后者是"没查库还想给结论、结果被拦下"。**真正要当故障看的是 `unverified=true`。**


## 三、调用示例

### curl

```bash
curl -X POST http://47.121.183.81:8200/api/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"环潭供电所上个月的线损率"}' \
  --max-time 90
```

### Python

```python
import requests

resp = requests.post(
    "http://47.121.183.81:8200/api/ask",
    json={"question": "环潭供电所上个月的线损率"},
    timeout=90,                      # 一定要给够，单次可能 30 秒
)
resp.encoding = "utf-8"
data = resp.json()
print(data["answer"])                # ← 展示这个
print("理解为：", data.get("fixed_question"))
```

不想装 requests 也可以用标准库：

```python
import json, urllib.request

body = json.dumps({"question": "环潭供电所的线损率"}, ensure_ascii=False).encode("utf-8")
req = urllib.request.Request("http://47.121.183.81:8200/api/ask", data=body,
                             headers={"Content-Type": "application/json"})
with urllib.request.urlopen(req, timeout=90) as r:
    data = json.loads(r.read().decode("utf-8"))
print(data["answer"])
```

### Java

```java
import java.net.URI;
import java.net.http.*;
import java.nio.charset.StandardCharsets;
import java.time.Duration;

var client = HttpClient.newBuilder()
        .connectTimeout(Duration.ofSeconds(10)).build();

String body = "{\"question\":\"环潭供电所上个月的线损率\"}";
var req = HttpRequest.newBuilder()
        .uri(URI.create("http://47.121.183.81:8200/api/ask"))
        .timeout(Duration.ofSeconds(90))            // 关键：给够时间
        .header("Content-Type", "application/json")
        .POST(HttpRequest.BodyPublishers.ofString(body, StandardCharsets.UTF_8))
        .build();

var resp = client.send(req, HttpResponse.BodyHandlers.ofString(StandardCharsets.UTF_8));
System.out.println(resp.body());                     // JSON，取 answer 字段
```

## 四、健康检查

```
GET /health
→ {"ok": true, "model": "qwen3.8-max", "name_fix": true}
```

| 字段 | 含义 |
|---|---|
| `ok` | 服务活着（能应答） |
| `model` | 当前默认模型 |
| `name_fix` | **纠错/归一是否生效**。为 `false` 时会多一个 `name_fix_reason` 说明原因 |

建议在你们那边加个心跳/探活。**探活建议判 `ok == true` 就够了**；
`name_fix` 是给我们运维看的功能健康度，`false` 时服务仍能答（只是不做错字纠正），
不需要你们报警，但**发现 `false` 请告知我们**。

> 注：`name_fix` 字段是最近一次更新加上的。如果你们那边只看到 `ok` 和 `model`，
> 说明服务器还没更新，不影响调用。

## 五、怎么问效果最好

**直接用大白话问就行**，不用自己拼时间地点。下面这些都能正确理解：

| 你问 | 系统会理解成 |
|---|---|
| 环潭供电所的线损率 | 环潭供电所 · 今年 1-9 月累计 |
| 环潭供电所**上个月**的线损率 | 环潭供电所 · **2026年8月** |
| **本月**的售电量 | 全市 · **2026年9月** |
| **环谈**供电所的售电量 | 自动纠正为**环潭**供电所（错字/同音字） |
| **凉水**供电所的售电量 | 自动归一为**两水**供电所（简称） |
| **公家棚**的线损率 | 自动归一为**龚家棚**台区（地名层） |

**错字、简称、漏写时间地点，都不用预处理**，直接传原文。

没写地点 → 默认**全市**；没写时间 → 默认**今年 1 月至今（累计口径）**。
这两项在 `scope` 里能用 `place_is_default` / `time_is_default` 判断出来，
如果前端想提示用户"我按全市理解了"，读这两个字段即可。

### 已知边界（避免误判成故障）

1. **"某供电所上个月"这类问法通常查不到值**。数据表里供电所粒度**只有年度和本年累计，
   没有当月口径**，且月度数据本身有缺失。系统会明确回答「X月数据缺失，最近可用的是…」，
   这是正常的，不是报错。
2. **当年数据用"本年累计"口径**（如 2026 年 1-9 月），不是"全年"。
3. 库里没有的指标（酒店入住率、GDP 等）会**如实拒答**，这是设计要求。

## 六、注意事项

1. **超时设 90 秒**。单次问答要查库 + 调大模型，5~30 秒是常态；超时设太短会拿不到结果。
2. **别高并发**。服务是单进程多线程，并发能力有限。如果要做批量，**串行调用**，
   或提前跟我们对一下节奏。
3. **接口没有鉴权，而这个地址是公网 IP** —— 也就是说，**知道地址的人都能查到全部业务数据**。
   请勿把地址转发到外部、不要写进对外文档或截图；如果要做正式系统，
   建议提前跟我们说，我们加一层鉴权或改用内网地址。
4. 需要**新指标 / 新口径**，或发现答案不对，找我们反馈（附上 `input_question` 和
   `fixed_question` 两个字段，能直接定位问题）。
