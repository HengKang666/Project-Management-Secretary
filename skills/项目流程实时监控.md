# 技能：项目流程实时监控

## 一、解决什么问题

**每天上线，一眼看到：我（这个角色）当前有几个项目在跟进、都是什么项目、哪些逾期。**
回答的是「我今天该盯哪几个」，不是一份全市报告。

**同一个技能，看哪一段随角色变（回答不固化）**：

| 角色 | 范围 | 看哪一段 |
|---|---|---|
| 审批人（各审核节点） | 本节点经手的单 | **申请阶段**：我这儿还有几单、最久的是哪几个 |
| 项目负责人 / 所长 | 本所 / 本人负责 | **执行阶段**：我名下几个在施工 / 待验收、哪些逾期 |
| 县公司 / 市公司 | 本公司 / 全市 | 两个阶段都要，按所汇总 |

## 二、怎么拆（一步一步）

1. **先定范围**（按角色），只看范围内的未完结项目。
2. **按阶段分组**：申请阶段（审核通过之前）／执行阶段（审核通过待施工、施工中、施工完成待验收）。
3. **排除不计入在办的**：已驳回、已取消、草稿；状态值在字典里没有登记的单独列「状态未登记」。
4. **逐单算进入当前阶段的天数。**
5. **判逾期**：有计划完工日的才判 —— 今天 > 计划完工日 → 逾期，超多少天。
6. **没有计划完工日的（实测全库 99% 都是空的）不许判「逾期」**，改用同类相对口径：按同一缺陷类型统计当前在办项目的在办时长，**超过 P75 = 偏久、超过 P90 = 危险**。
7. **完工未上报**：状态停在「施工完成待验收」超过 90 天 → 单独成条。
8. **按紧急度排**：逾期 > 危险 > 偏久。
9. **汇总**：共几个在跟进、申请阶段几个、执行阶段几个、逾期几个。

## 三、回答模板（严格照着写，这就是最终给人的那段话）

**总长纪律：不超过 250 字。**
**回答只有下面这些内容，不要再换个标题重复一遍。**

截至 2026 年 9 月 16 日，您（环潭供电所）名下 8 个项目在跟进：申请阶段 8 个、执行阶段 0 个。
逾期/危险：0 个。
偏久：X 个（比同类型在办项目偏久）：…
今天先处理：…

**两条硬约束**：
- **项目少就直接说「没有逾期、没有危险」**，不许为了凑四段硬写。
- 没有计划完工日的说「比同类偏久」，不许说「逾期」。

### 各段必须包含的内容


1. **概览** —— 截至今天，您名下共 N 个项目在跟进（申请阶段 X 个、执行阶段 Y 个）
2. **逾期 / 危险的** —— 逐条：项目名 / 台区 / 金额 / 挂了多久 / 属于哪一档
3. **偏久的** —— 逐条同上；没有就写「无」
4. **今天建议先处理** —— 按紧急度排序，说清该谁动

## 四、回答约束

- 必须以「截至 X 年 X 月 X 日」开头。
- **必须点名具体项目**，不许只说「存在进度风险」。
- **不许把整个系统的审批积压当成这里的结论** —— 那属于「各层级审批」。
- 没有计划完工日的说「比同类偏久」，**不许说「逾期」**，两者不许混用。
- 清单逐条列全；数量与列出的条数必须一致。
- 只看当年创建的项目（历史遗留会把平均在办时长拉到 1400 天以上），并在回答里注明范围。

格式与硬规则按《判据规则》「十五、输出格式」「十六、硬规则」；判断标准按「一、前置」「二、层级与范围」「七、进度异常」「十七 17.2」。
