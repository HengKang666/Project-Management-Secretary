# 技能：预算分配

## 一、解决什么问题

一份年度预算分配通知到手，要说清这条链上的四件事，且能直接上报：
钱是怎么算出来的 → 今年该治什么 → 钱具体花在哪些项目上 → 做完能到什么程度。

## 二、回答模板（**先看这一节：这就是最终给人的那段话**）

**长度：默认不超过 400 字。回答只有下面这一段，不要再另起「一、二、三」分节、不要换个标题重复一遍。**

结论：环潭供电所本期分配 48.20 万元，占随县公司 6.02%、占全市 2.56%；上期金额未查得，同比无法判定。
主因：台区线损（权重 0.15、贡献 15.00 分）、用户平均停电时间（0.15、14.61 分）、全渠道受理工单（0.15、13.82 分）三项问题导向指标居前，资源向本所倾斜。
今年怎么花：聚焦降线损、减停电、提电压三个方向，按「目标匹配度 → 优先级 → 金额」排序装填。
排入 7 个项目、合计 47.91 万元：
1. 公变10#台区｜线缆类-电缆｜14.64 万元｜减停电
2. …（一行一个：项目名｜缺陷类型｜金额｜对应哪个目标。**不写「已用/剩」流水**）
剔除 1 个：八家庙4#变压器配电箱更换｜设备类-柱上变压器｜1.03 万元｜轮到它就超出可用余额，整笔装不下。
结余 0.29 万元（= 分配 48.20 万元 − 排入 47.91 万元）。
核对：储备 8 条合计 48.95 万元 ＝ 排入 7 条 47.91 万元 ＋ 剔除 1 条 1.03 万元。
做到什么程度：线损率 3.65%→2.80%、平均停电时长 6.60→4.50 小时/户、IEC 指数 98.97→99.50（建议值，需审定）。
风险：2025 年评分明细缺失，同比无法开展；结余 0.29 万元需明确处置。

**三条硬约束**：
- **16 项指标不要逐项列 16 行**，只写贡献最大的 3~4 项。
- **六项成效不要铺六行**，只写有关键项目支撑的那几项，其余合并成一句「售电量、故障报修、意见工单无直接项目支撑，暂不设目标」。
- **所有合计都必须来自 SQL 的 SUM，不许在脑子里加**。你报出的每一个合计，都要能在本次查询结果里找到对应的那个数。

### 唯一允许追加的内容：分配分布清单

**只有当问题明确要求「各公司 / 各所分别多少、占比多少」时**，才在模板那段之后另起一节列清单（清单不占 400 字）：
按所属公司分组，逐所列「金额 + 占比」，一家公司一块、一所一行，末尾给本公司合计，最后给全市合计。
**一个所都不许省，不许用「前 N 名」「其余均在…以下」「等」概括**；说「20 个所」就要列满 20 条，报数前先数一遍。
所级占比的分母与公司级保持一致（都按占全市合计），并写明分母是什么。清单里不再解释一遍主因。
**每列完一家公司，把这一块的金额加一遍，必须等于该公司的合计；对不上就是分组错了**（典型错法：把 A 公司的所划到 B 公司名下）—— 先按所属公司分组再排，不许跨公司混排。

## 三、角色与维度（回答不固化）

| 角色 | 范围 | 看什么 |
|---|---|---|
| 分配方（市公司 / 县公司） | 全市 / 本公司 | 横向：各公司、各所分别分到多少、占比多少、谁高谁低、有没有异常偏高 |
| 供电所（被分配方） | 本所 | 纵向：我分到多少、16 项里哪几项决定了这个数、比上期增减、这笔钱今年怎么花 |

问到哪一段就答哪一段，但要把那一段答全；**问题没问到的段落不要写**。

## 四、分析步骤（**你自己私下走，不要写进回答**）

1. 先确认这个所在库里的名称写法（简称 / 全称 / 有没有空格），对不上就如实说明，不要硬凑。
2. 先确认库里有哪些期次（往年逐项评分可能没有），先查有没有；作废 / 删除的记录一律排除。
3. 把 16 项按「分类 × 权重 × 标准分」摊开，算每项对总分的贡献。
4. 判方向：**得分高 = 越需要资源，不是表现好**。问题导向类（线损、工单、停电时长、低电压）分高 = 问题重；基础信息类分高 = 规模大。
5. 把原始值为空或 0 的项剔出来 —— 那是没采集到数据，不能当拿钱的理由。
6. 在问题导向类 + 历史预算执行里挑**标准分高且数据有效**的 2~3 项 → 今年治理目标。
7. 每项写清：现状 → 按什么规则算分 → 提到什么水平能带来多少分 → 对总分的贡献。
8. 拿目标去项目台账对项目：一条都要能讲出为什么它在治那个目标。
9. 排序：目标匹配度 → 优先级 → 金额（金额小的往后排，便于凑满）。
10. 按这个顺序逐笔判断「已装入 + 本项目 ≤ 可用余额」；**装不下就整笔剔除，绝对不许拆开只装一部分**。
    **剔除的唯一理由就是「装不下」**（累计 + 本项目 > 可用余额）。**不许因为「类型未明确」「匹配度低」「金额太小」就把装得下的项目剔除** —— 排序只决定先后，不决定要不要。**只要装得下就必须排进去**；全部装得下就全部排入。
11. **排入清单定下来后，用一次 SQL 把这几条的金额 SUM 出来**（这是排入合计），**不许在脑子里加**；结余 = 可用余额 − 排入合计（这一个减法可以手算）。
12. 剔除项也用一次 SQL SUM 出合计，写核对行：储备合计 = 排入合计 + 剔除合计，对不上就回去查。
13. 六项成效逐项给「现状 → 目标 → 依据」，依据必须落到排入的项目上；标「建议值，需审定」；没依据的写「暂不设定目标」，不许编数。

## 五、回答约束

- **不许凭印象给名次**：要么本次查询里确实取到了名次字段，要么自己把明细排序后再报；报出来的名次必须能被同一段里列出的明细验证。
- **同一个项目的金额全篇只能有一个值**，不许一处 14.64 万元、另一处 11.62 万元。
- **数量跟列出的条目对不上就是没答完**，报数量前先数一遍。
- 金额万元两位、比率两位；编号（缺陷类型、状态）一律翻中文。
- 不许出现表名、字段名、英文标识、SQL、期次编码；不许写「数据来源」「口径声明」这类说明段。
- 查不到的写「未查得 / 无法判定」，不许估算、不许补 0、不许拿别的年份顶。

格式与硬规则按《判据规则》「十五、输出格式」「十六、硬规则」；判断标准按「九、金额合理性」「十三、年度计划类」。
