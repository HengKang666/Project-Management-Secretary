# 技能：实时监控

## 一、解决什么问题

**单据状态一变，就判断这一步正不正常**；不正常立刻推给该环节的责任人，而且**没处理就一直提醒**（自回归）。

回答的是「哪张单、哪一步、越了哪条线、超了多少、该谁动」，不是一份事后的汇总报告。

**不同环节、不同责任人（回答不固化）**：
- 审批环节的变化 → 推给当前节点的审批人
- 施工 / 验收环节的变化 → 推给项目负责人、所长
- 金额 / 明细类的问题 → 推给财务口径的角色

## 二、怎么拆（一步一步）

1. **认出这次变更**：哪张单、从什么状态变到什么状态、谁在什么时候改的。
2. **算停留**：它在新状态停了多久；同类同状态通常停多久。
3. **逐条过阈值**：
   - 停留越阈：一般环节 >30 天，审批环节 >90 天
   - 状态倒退：已到「审核通过待施工」及之后，又回到「提交审核 / 审核中」
   - 状态跳级：未经审批直接进入「审核通过待施工」及之后
   - 重复驳回：同一张单被驳回 ≥2 次
4. **越阈就说三句**：越了多少、超了多久、该谁管。只说「超标了」不算。
5. **推给对应角色**，并登记「待处理」。
6. **自回归**：下次这张单状态再变、或次日复核时，**仍未处理就重新提醒一次，并标注「已连续 N 天」**，直到处理。
7. **没有阈值的指标不要报** —— 没有判据就没有异常。

## 三、回答模板（严格照着写，这就是最终给人的那段话）

**总长纪律：不超过 150 字，一段话说完。**
**回答只有下面这些内容，不要再换个标题重复一遍。**

白鹤湾6#台区（淮河供电所，1.55 万元）于 2026-04-17 由「县公司运检部审核」流转到「县公司财务部审核」，到系统当天已停留 152 天，超过 90 天阈值且未处理，属连续超阈提醒。请县公司财务部审核节点优先处理；同类单还有 N 张。

**两条硬约束**：
- **不要分小节**，一段话说完。
- 没越阈就直接写「本次变化未越阈」，不许硬编异常。

### 各段必须包含的内容


1. **这次变化** —— 哪张单、从什么状态到什么状态、什么时候改的
2. **判了什么** —— 逐条说越没越阈、超了多少
3. **该谁动** —— 责任人 + 建议动作（没处理过的标明「已连续 N 天未处理」）

## 四、回答约束

- 一条提醒必须说清 项目 / 台区 / 金额 / 从什么状态到什么状态 / 越了哪条 / 超了多少 / 该谁处理，缺一样都不算完。
- **不许把「审核中数量多」当成这个技能的结论** —— 那是审批积压（「各层级审批」的事）。
- 状态一律翻中文。
- 没越阈就明确写「本次变化未越阈」，**不许硬编一个异常出来**。

格式与硬规则按《判据规则》「十五、输出格式」「十六、硬规则」；判断标准按「七、进度异常」「十一、实时监控阈值」「十七 17.5」。
