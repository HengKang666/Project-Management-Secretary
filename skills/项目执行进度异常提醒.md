# 技能：项目执行进度异常提醒

## 一、解决什么问题

**只看执行阶段的进度 —— 哪个项目要出事。** 回答的是「哪些落后、哪些逾期、哪些年内完不成、卡在谁那里」。

**不同角色、不同范围（回答不固化）**：

| 角色 | 范围 | 看什么 |
|---|---|---|
| 项目负责人 | 本人负责的项目 | 我的项目落后了 |
| 所长 | 本所 | 本所哪些项目落后 |
| 县公司 / 市公司 | 本公司 / 全市 | 哪些所进度差、哪个环节是瓶颈 |

## 二、怎么拆（一步一步）

1. **先定范围**，只看执行阶段的（审核通过待施工、施工中、施工完成待验收）。
2. **排除**：草稿、已驳回、已取消；状态值在字典里没登记的单独列「状态未登记」。
3. **四类异常逐条判**：
   - 超期：有计划完工日且已过（超 15 天以上），分 15–30 / 31–90 / 90 天以上三档
   - 落后：已过计划工期一半，状态仍停在「审核通过待施工」之前
   - 停滞：需要「状态最后变更时间」，**本库没有这个字段 → 一律写「无法判定」，不许拿别的字段当替身**
   - 快要完不成：按当前进度估算所需天数 > 当年剩余天数
4. **没有计划完工日的（实测 99% 是空的）不许判「超期」**，改用同类相对口径：同一缺陷类型的在办项目，超过 P75 = 偏久、超过 P90 = 危险。
5. **钱花了没动**：金额排本所前 10 位，且状态停在「审核通过待施工 / 施工中」超过 90 天。
6. **逐条说清**：哪个项目、拖了多久、多少钱、卡在谁那里。
7. **按超期天数排序**，给「先催哪些、该谁动」。

## 三、回答模板（严格照着写，这就是最终给人的那段话）

**总长纪律：不超过 250 字。**
**回答只有下面这些内容，不要再换个标题重复一遍。**

环潭供电所执行阶段项目 0 个，未发现进度异常。
（如有异常）共 N 条、合计 X 万元，其中超期 A 条、偏久 B 条、钱花了没动 C 条：
1. 项目名｜当前状态｜无计划工期｜比同类偏久 45 天｜X 万元｜卡在施工环节
建议：先催 …（按超期/偏久天数排序，写清该谁动）。

**两条硬约束**：
- **没异常就一句话收尾**，不许为了凑段写满四段。
- 不许只写「存在进度异常」了事；每条要说清哪个项目、多久、多少钱、卡在谁那里。
- **阈值和条目必须自洽**：说「同类 P75 = 114 天」，那么 117 天那条就必须判成「偏久」，不能一边给阈值一边说「均未超」。**每条都要当场和 P75 / P90 比一遍**，超了才进「偏久 / 危险」，没超的归到「正常跟进」那一句里。
- **概览和清单必须一致**：概览说「未发现异常」，后面就不许再列异常清单；清单里列了 N 条，概览就必须写「N 条」。

### 各段必须包含的内容


1. **异常概览** —— 几条、合计多少钱、按四类分档各几条
2. **逐条异常清单** —— 项目名 / 当前状态 / 计划完工（没有就写「无计划工期」）/ 超了多少天或偏久多少 / 金额 / 卡在谁那里
3. **钱花了但没动的** —— 金额排前几位的单独说
4. **下一步建议** —— 按超期天数排序，写清该谁动

## 四、回答约束

- **不许只写「存在进度异常」** —— 每条必须说清：哪个项目、拖了多久、多少钱、卡在谁那里。
- **不许拿「审核中数量多」当这个技能的结论** —— 那是审批积压，属于另一个技能。
- 计划完工日为空的**单独列「无计划工期」**，既不当异常也不当正常；不许判「逾期」。
- 「停滞」本库没有判据，一律写「无法判定」，**不许拿别的字段硬算**。
- 清单逐条列全；数量与列出的条数必须一致。

格式与硬规则按《判据规则》「十五、输出格式」「十六、硬规则」；判断标准按「一、前置」「七、进度异常」「十七 17.2」。

## 五、标题判据（定时提醒只报这一句；**按优先级取第一个有命中的**）

> 明细追问（/api/ask）才展开其余维度；**标题永远只报一个维度**，否则每次报的都不是同一件事。

| 优先级 | 维度 | 判据 | 标题模板 |
|---|---|---|---|
| 1 | 钱花了没动 | 已发生金额（reality_total）本所前 10，且状态停在 3/6 超 90 天 | 今天有 N 个项目钱花了没动 |
| 2 | 超期 | 已过计划完工日 15 天以上且未完工 | 今天有 N 个项目超期未完工 |
| 3 | 同类偏久 | 执行阶段且停留超同缺陷类型在办项目的 P75 | 今天有 N 个项目比同类偏久 |
| 4 | 无异常 | 以上都无命中 | 今天无项目进度异常 |

**说明**：本库 99% 没有计划完工日，第 2 条基本用不了；**实际主力是第 1、3 条**。
「停滞」维度因库里没有"进入当前状态的时间"字段，**一律写"无法判定"，不许拿 update_time 冒充**。
