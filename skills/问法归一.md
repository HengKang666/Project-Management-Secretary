# 问法归一（残缺问法 → 标准口径）

> **用户不会提完整的问题。** 这份文档把口语、残缺、简称的问法统一映射到同一套标准口径，
> 保证同一个问题换个人问、换个说法问，答案一致。
> 本服务每个问题进来都会检索这份文档；分析类问题同时还会取《分析规则》当判断标准。
> **规则里没写的，不许自己另立一套**。

## 一、三条缺省约定（问题里没说的，一律按这三条补，不要自己另定）

1. **时间没说** → 用系统已算好的【统计范围】里的期间（算到今天）。**不要**自己补「今年」「最近一个月」「上个月」。
2. **范围没说** → 用**提问人的身份范围**（系统提示里给的身份与数据范围）。
   没有身份信息时，按全市作答，并在回答里写明「按全市」——不许默默换范围。
3. **对象没说** → 按问法的默认对象：
   - 「待处理 / 待审批 / 先办哪几张」→ **工单审批任务**
   - 「项目 / 工程 / 治理」→ **缺陷治理工单**
   - 直接报指标名的 → 该指标本身

## 二、问法映射表（左边这么问 = 右边这个口径）

| 用户可能这么问 | 标准口径（照这个查、照这个答） |
|---|---|
| 有哪些项目待处理／有什么要我办的／我这儿有多少待审批的 | **停在我这个审批节点、状态为「待处理」的审批任务**（审批任务表 `t_work_order_audit_task`；只算「待处理」，已完成／已驳回／处理中都不算）。**不是** `t_power_work_order.work_status='2'` —— 那是全库「审核中」，不等于某个人的待办。停留天数 = 系统当天 − 进入本节点的时间。 |
| 卡得最久的是哪几个／挂了多久／压了几天 | 同上面的集合，按**停留天数降序**。逐条给：工单名 / 所属所 / 金额 / 停留天数 / 分档（**≤15 天正常、16–90 天偏慢、>90 天积压**）。 |
| 今天我先办哪几张／下一步做什么／给个建议 | 同「待我审批」集合，按**提问角色的关注口径**排序取前 5：**财务按金额、运检按风险与专业、领导按总量**；每张都要给「为什么先办它」。 |
| 有没有漏掉的／该到我这儿却没到 | **遗漏**：上一节点已完成且未驳回、但本节点没有生成「待处理」任务。**与「积压」是两件事，分开报**，没有就明确写「无遗漏」。 |
| 有没有项目逾期／哪些逾期了 | 工单或项目**当前状态停留天数超过该环节允许停留天数**（一般环节 30 天、审批环节 90 天）。没超阈就明确写「未逾期」。 |
| 钱花了没动／执行进度异常 | 已进入执行阶段（施工中 / 施工完成待验收）却没有对应的施工或完工记录；或实际进度落后于计划。报「落后多少、卡在哪个环节、卡在谁」。 |
| 哪些申请资金明显不合理 | 三项依据一起给：该所当年可用余额、单笔金额占余额比例、同类项目历史单价。明显不合理 = 金额 > 可用余额，或单价显著高于同类历史值。 |
| 情况怎么样／整体情况／最近如何 | 六项治理成效指标（售电量、台区线损率、故障报修工单、意见工单、用户平均停电时长、故障跳闸次数）＋ 预算安排与执行进度。 |
| 这个数是多少／有多少个 | 纯查数：取到数直接答，**不给判断、不加分析、不编标准**。 |

## 三、一致性与反例（这几处最容易答歪）

1. **口径只认一份**：同一场会话里，同一个对象的口径**必须与上一次一致**。
   上一轮定了「随县、财务部这个节点」，这一轮换了问法也不能悄悄变成全市。
2. **严禁把「全库的量」当成「我的待办」** —— 这是本业务最容易出的错（把全库审核中当成某人待办）。
3. **不许按创建年度过滤**：卡得最久的往往就是往年创建的项目，滤掉正好把最该清的藏起来。
4. **数量与列出的条数必须一致**：说「积压 N 张」，清单里就得正好是 N 条。
5. **问法残缺不是拒答的理由**：按上表映射后照常作答；只有映射后确实查不到数据，
   才写「未查到」并说明缺什么数据。**不许因为问题问得不完整就回一句「未找到相关信息」。**
6. **状态、缺陷类型一律翻中文**；停留天数与金额口径按《判据规则》。
