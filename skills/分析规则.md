# 分析规则（项目管理秘书 · 分析类问题专用）

> 用途：**只**给「分析」类问题用（判断、原因、趋势、对比、是否异常/是否合理）。
> 查数类问题（问某个数、清单、排名、占比）**不看这份文档**，取到数直接回答。
> 本服务在判出题型为「分析」时检索本文件，按它当判断标准；**规则里没写的标准一律不许自己编**。

## 一、分析的统一结构（每道分析题都要给全这四段）

1. **结论**一句话先说完（是/不是、超了多少、差多少）。
2. **依据**：支撑结论的数字，必须是从库里查到的，写明范围与期间。
3. **判断标准**：用的是哪条阈值/口径。**标准来自本文件**；本文件没有的，就写「无判定标准，仅呈现事实」。
4. **建议**：谁该做什么。没把握就写「建议核实」，不许编原因。

**只有结论没有数字 = 不合格；只有数字没有判断 = 不合格。**

## 二、通用分析流程（五步，顺序不能换）

1. **定对象与范围**：分析谁（哪张单 / 哪个所 / 哪个指标）、哪个期间。期间按问题的统计范围，不许自己缩到某个月。
2. **取数**：现状值 + 对比值（同期 / 上期）+ 需要的时间序列，一次查全。
3. **找标准**：在本文第三节找该场景的阈值；找不到就明确写"无判定标准"。
4. **比标准下判断**：给出「是/否 + 差多少/超多少」。
5. **给建议**：落到具体的人或岗位。

## 三、各场景的判定标准

### 3.1 逾期 / 卡住（项目、工单停在某状态）
- **逾期 = 当前状态已停留天数 > 该环节允许停留天数**：一般环节 30 天，审批环节 90 天。
- 必须报齐：单名或台区、金额、当前状态（中文）、停留天数、超阈天数、该谁处理。
- 未超阈要明确写「未逾期 / 未超阈」，不许硬编异常。
- 连续未处理：标注「已连续 N 天」，直到处理。

### 3.2 线损率
- 判定：**< 3% 优秀；3%–5% 正常；> 5% 偏高需关注**。
- 口径：一律指**台区线损率**。
- 同比 = 与去年同期比；涨跌幅 =（本期 − 同期）/ 同期。
- **同期数据查不到**：只能给本期值与是否越阈，写「同期数据未查得」；**绝对不许估算同比**。

### 3.3 预算执行
- **执行率 = 实际执行金额 / 预算总额**：< 80% 偏低；80%–110% 正常；> 110% 超预算。
- **余额必须按年度对齐**：可用余额两侧都按当年度算。**绝对不许用「含往年结转」解释余额为负**——出现负数就是口径没对齐，回去按年度重算。
- 花不完的判断：按「单项目均价 × 剩余时间可做项目数」估，并把用到的两个数写出来。

### 3.4 投入产出
- **投入产出比 = 经济效益 / 实际投入**：< 1 需关注；>= 2 优秀。

### 3.5 资金合理性（新申请 / 已批出的单）
- 依据三项：① 该所当年可用余额；② 单笔金额占可用余额的比例；③ 同类项目的历史单价。
- **明显不合理** = 申请金额 > 该所可用余额，或单价显著高于同类历史值。
- 报的时候三项都要写出来，只给结论等于没给。

### 3.6 审批积压 / 今天先办哪几张
- 积压 = 停在本节点超过上表阈值的单据数量。
- 必报：卡最久的几张（单名、金额、卡了多少天）、总数。
- 排序建议：**卡得久 → 金额大**，并说明排序依据。

### 3.7 执行进度异常
- 异常 = 实际进度落后于计划进度，或计划完工日期临近但完成度明显不足。
- 必报：落后多少（天 / 百分点）、卡在哪个环节、卡在谁那里。

## 四、硬规则（违反即不合格）

1. 每个判断后面必须紧跟数字与标准；**没有数字的判断不许写**。
2. 库里没有的写「未查得」，**不许估算、不许补 0、不许拿别的年份顶**。
3. **不许编原因**：说不清就写「原因需结合现场核实」。
4. **不许因为查不到就整体拒答**：先给「能确定的部分」，再写「还要什么数据才能下结论」。
5. 时间用业务说法（「截至 2026 年 9 月」）；状态、缺陷类型一律翻中文。
6. 金额一律万元、两位小数；比率与时长两位小数。
7. 回答用纯文本，不用 markdown 标题/加粗/表格符号；清单一条一行列全，不许用「等 N 条」代替。
8. 不要提表名、字段名、SQL、查询过程，也不要写「数据来源」「口径声明」这类说明段。
